# 传输模块与直连

本文是客户端与 daemon 间的传输设计，负责分层、路径选择、网络切换、安全绑定与路径状态展示；不定义账户、历史同步或原生 CLI 行为。范围和信任边界见 [scope.md](scope.md)，既有业务信封与指令语义见 [architecture §10](architecture.md#10-报文同步和指令)，实测依据见 [transport-notes.md](transport-notes.md)，实施阶段及全部未决事项见 [plan.md](plan.md#传输模块与直连)。这是已确定、尚未接入产品的设计；当前实现仍只走中继。

## 1. 分层与职责

用户操作不依赖路径：打洞成功且性能不差于中继时使用直连，失败走中继，首个请求不等待 ICE。增加或移除 Path 不改变上层业务。手机可以查看当前路径，路径切换不打断操作。

通信分成两类：

| 通信 | 负责者 | 内容 |
|---|---|---|
| 与 server 通信 | 现有账户、同步和推送组件 | 账户与设备鉴权、成员状态与租约、事件历史先落库再推送、多设备同步、图片显示副本、推送；不经过下面的 Link |
| 与对端设备通信 | 传输模块 | 客户端 ↔ daemon 的指令与结果、终端流、上传分块、只读查询及 `GetSharedFileChunk` 下载；后者的接口依赖见 [计划](plan.md#传输模块与直连) |

```text
会话 / 指令 / 终端 / 文件 / 电脑状态
共享组件：封装加密、验签鉴权、幂等、并发准入、结果协调
                         │ 不透明的已封装帧
Link：call / open stream / transfer / status（只读、可订阅）
                         │
Router：可用性、优先级、连接代次、探测、升级、回退
                         │
Path：RelayPath / DirectPath / 后续可增加的路径
                         │
信令：经中继交换已签名、端到端加密的协商与控制载荷
```

四端同构：Go `internal/transport`、网页 `web/src/transport`、Android `core/transport`、iOS `RACore/Transport`。接口同名同义，共用路径失效、重复/迟到/乱序、网络变化、取消、背压与恢复的一致性场景。iOS 的 WebRTC SDK 由 App 层注入适配器，纯 Swift core 测试不依赖完整二进制 SDK；Android 平台网络和 JNI 回调通过适配器进入 core。

Link 表达一次调用、有序可靠双向流、大块传输与只读状态；业务不能根据 status 决定重发或授权。Router 按用途选择路径，Path 仅收发密文帧，不持有内容密钥，不解读业务。路径的超时、取消、错误码和背压语义一致。信令借 RelayPath 送达，协商期间业务仍可走中继；账户登录、安全状态同步不是信令的替代品。

daemon 只有一个共享 dispatcher：拥有安全 endpoint、持久接受记录、执行生存期、8 个执行槽和有界的同 ID in-flight 结果协调器；两路进入同一入口，不随 WS/PeerConnection 各建一套。连接关闭取消的是该路等待者，不能把 CLI 操作当作已撤销，也不能连带销毁另一条路的安全状态。信令等待有单独限额，不占满执行槽；历史同步保持独立调度。

## 2. 路径与选型

RelayPath 适配既有 HTTPS `Forward`、主 WebSocket 转发和独立终端 WebSocket。第 0 期先抽离这部分；业务、历史、通知和图片存储语义不变，网络失效恢复按第 4 节修正。

DirectPath 第一期四端统一用 WebRTC DataChannel，daemon 用 Pion；自建 STUN，不部署 TURN，不依赖第三方 STUN/TURN 服务。UDP 被挡、NAT 不可穿透或 STUN 不可用时用现有 HTTPS/WSS 中继。浏览器保持默认 mDNS/候选隐私策略，不申请音视频权限来获取更多地址。

选择 WebRTC 是因为浏览器可用、ICE 与原生端有共同实现路径；不是因为它吞吐更高。[回环与丢包实测](transport-notes.md#2-吞吐与排队)表明 QUIC 在吞吐、资源和部分丢包尾延迟上更好，但该 QUIC 原型假定 UDP 已可达，没有验证穿透或手机集成。本期不引入 QUIC；Path 不能暴露 PeerConnection/SDP 给上层，以便以后原生端加 QUIC 时仍复用 Link、安全门和恢复语义。

大块传输使用**独立 PeerConnection**，不能仅分 DataChannel 后就认为拥塞隔离。指令/审批优先于终端，终端优先于 bulk；各用途独立有界队列，探测保留发送预算。可靠有序 DataChannel 承载业务；探测可用不重传的小通道，探测丢失不影响业务完整性。默认传输片以 16 KiB 为起点，遵守协商出的 `maxMessageSize` 并预留 framing 空间；768 KiB 应用块不能直接当 DataChannel 消息发送。

先封装、再分片，接收端有界重组后交共享安全门验证，未认证的数据不推进业务水位。每 peer 和全局都限制排队字节、重组大小/数量/期限、候选数量/速率及并行 ICE 尝试；不得随文件大小缓存整文件。上传先在单个应用块内分片，按已持久确认偏移推进，不能直接照搬原型的八块并发窗口。数值未定项见 [计划](plan.md#传输模块与直连)。

## 3. 选路与热备

1. 建立可认证的中继路径即可交付业务；后台有界探测 direct，失败退避，网络代次变化后重新探测。
2. 完成设备绑定并用实际业务类型测得 direct 不差于 relay 才升级。交互看 p95，bulk 独立看同文件吞吐，不能用低 RTT 替代文件性能判断。
3. direct 可用期间，指令与终端小流量保持热备：**同一逻辑流、同一序号、同一授权操作同时经 direct 与 relay 投递**，取先到的有效结果，接收端只应用一次。文件正文不双发。中继保留少量交互流量是无感切换的代价。
4. 失效立即把新业务交给可用备用路，不等 ICE `failed`。恢复后至少观察 5 秒稳定期、重新证明 direct 不差再升级，避免反复切换。关直连时安全退回 RelayPath 并停止 ICE/STUN。

### 指令与结果

同一个逻辑操作只准备和授权一次。换路或双发沿用原 request ID、原授权载荷与原截止时间；必要的重新封装不改变业务身份。两路通过共享接受门后合并同 ID 的执行与等待者，只占一个执行槽；有界结果协调器让第二路等待已有结果，不再次调用 CLI。只读查询允许重复求值，不能以它证明有副作用指令至多执行一次。

先验证 daemon 签名和结果绑定再完成调用；未经认证的“成功”不能结束 unknown。持久接受记录只有开始而没有可信结果时继续 unknown，不换新 ID、不延长期限、不把取消 HTTP 等同取消原生 CLI。连接代次也不产生新业务 ID。接受日志继续受 8,192 条、16 MiB 和截止时间驱逐约束；过期记录不存在也不能重新接受过期操作。指令安全语义的其余规则以 [architecture §10](architecture.md#10-报文同步和指令) 为准。

### 终端连续性

一条逻辑终端流对应一个 tmux control 连接，两方向各有路径无关的序号分配器、连续 ACK 水位和有界重放环。接收入口先验签授权，再按逻辑流/方向/序号合并重复、缓存缺口，按连续顺序应用一次；重复合法帧只确认，不再次注入或直接交给现有“重复即关流”的读循环。相同序号的冲突载荷拒绝，不以“重复”跳过安全验证。

输出 ACK 在客户端渲染消费队列完成后推进，输入 ACK 在 daemon 确认 tmux 输入命令结果后推进；写入 socket 不算应用成功。新增路径先交换已认证的流 ID、连接代次、双向连续水位，补发未 ACK 帧，以 barrier 确认某水位之前已连续应用，再纳入热备。切路不另开 tmux、不换逻辑 stream ID、不从零编号；旧路迟到回调不能关闭新连接，迟到有效帧仍按原流去重。

缺口超过重放窗口或积压超过预算时，明确结束旧逻辑流、建立新流并抓快照，不能跳号假装连续。不确定是否已注入的输入保留 unknown，不盲重打；快照只能恢复画面，不能证明按键执行次数。路径切换不调用产品终端 onClose、不清屏、不失焦、不重新抢尺寸；真正重建时保留旧画面，等新快照可用再替换。

### 分块续传

bulk 的应用层探测采用软期限：默认从 `max(500 ms, 4×近期 RTT + 调度余量)` 起，近期交互/切换窗口可每 50 ms 探测，空闲降频，后台停止。超预算启动备用路续传，不是判定电脑离线；ICE 事件负责后续清理与重新协商。250 ms 只可作为受控低延时条件的激进配置，[有限窗口实测](transport-notes.md#3-网络切换与热备)不能证明真实移动网络零误切。

上传只认 durable `persisted_bytes`，换路先查 Status，从已确认 offset 重传同字节；分块长度/哈希及传输归属照常验证。下载用 `GetSharedFileChunk`，按接收端已经验证并持久保存的连续偏移恢复，同一文件身份和版本不变，不能把本地“已发送”当进度。下载的授权和对象生命周期依赖见 [计划](plan.md#传输模块与直连)。进度不归零、不重选文件；未确认尾部不能计为已完成。

## 4. 网络切换与第 0 期中继修复

无感的条件是两端进程存活、至少一条路径可用、终端仍在重放窗口内；直连有效期间的小流量不等待故障判定。两路都断开、应用挂起或跨进程崩溃时不承诺即时回显或任意 CLI 的 exactly-once。此时保留画面、原请求身份和传输水位，输入缓存有大小和期限上限，不显示虚假的已送达。

现有中继自身也有弱点，不能等 DirectPath 才修。[实测与源码基线](transport-notes.md#1-既有中继与网络失效)是第 0 期的缺陷清单。服务通信仍由原组件负责，但统一接收网络代次与活性信号：

| 端 | 第 0 期修复设计 |
|---|---|
| 网页 | 除 online/offline、可见性、freeze/resume 外，在支持时订阅 `navigator.connection.change`；API 缺失由活性检测兜底。应用心跳按原始收帧更新，不等历史解密；前台用更短的心跳周期及多次缺失预算代替 60 秒静默 watchdog。换网立即试新连接，不等待旧 WS 关闭握手；主动唤醒同 ID 在途 Forward 的重试，不让旧 HTTP 独自等满约 45 秒 |
| Android | 跟踪默认 Network handle、LinkProperties/地址及能力变化，不只用 available/lost 布尔值；合并重复通知，有实际路径变化才推进代次。前台缩短 ping/失活预算，网络变化立即新建 relay 并协调原 ID 的在途调用，终端生存期从物理 socket 拆开 |
| iOS | NWPathMonitor 跟踪实际路径信息，不以 `availableInterfaces.first` 或接口名不变判断连接健康；同接口 Wi-Fi/DHCP 变化靠应用活性探测补足。前台缩短现有 20–40 秒的 ping 判定，恢复或路径变化即探测/换连接，原 ID 在途调用可提前重试 |
| daemon（macOS/Linux） | 接入系统接口/路由/地址变化通知及有界连通性检查，不仅靠现有 25 秒 ping + 20 秒等待。真实变化推进代次并新建 relay，触发原请求结果协调；执行上下文与单个主 WS 解耦，不因电脑换网重复执行 |

心跳间隔和连续缺失次数需按 RTT/调度预算验收后定值，见 [计划](plan.md#传输模块与直连)。不能把 bulk 排队、历史处理耗时、单次探测超时或系统的“网络已验证”状态当电脑离线。更短预算只使旧路变为可疑并先用备用/试新连接；必须由真实认证响应证明恢复，连续确认后退役旧路。重复网络通知合并，健康连接不因每次能力刷新都重建；旧代次回调不得覆盖新状态。这些机制控制误判代价，不声称所有网络绝不误判。

后台遵循既有平台生命周期，不维持伪音频/VoIP 或无限 ping。挂起前保存请求/文件水位和有界流状态，暂停计时器健康判定；回前台先核对成员状态/租约、恢复 relay、查询在途结果及 offset，再续接终端，direct 新代次后台做 ICE restart。不能以 socket 对象仍存在证明路径可用，也不能把休眠时长累计成连续丢包。网络信号只触发候选重建，ICE restart 仍需应用完成加密信令。

## 5. 协议与安全绑定

保留现有端到端信封加密、签名、AAD、防重放，DTLS 再包一层；不以 DTLS 替代设备授权。DTLS 指纹通过已配对设备密钥签名、端到端加密的信令绑定，不能信任 relay 普通元数据里的候选或指纹。

信令认证范围包含固定安全域/账户、两端 device ID、machine ID、协议版本、成员状态 hash、随机连接 ID 与 generation、协商角色和短截止时间；SDP 内的 DTLS SHA-256 指纹、ICE 凭据和候选一起受保护，追加候选带该代次与信令序号。先检查签名、成员角色、租约、目标与期限，再交 SDK；握手必须校验认证指纹，禁止关闭校验。建连后以已签名确认绑定双方 SDP hash、指纹及代次，避免跨连接拼接。重协商保持相同身份规则。

relay/direct 共用成员/租约/撤销校验、8 槽并发准入和接受日志上限；租约过期、移除设备与密钥轮换一致生效，不让旧 direct 会话永久续命。状态获取仍依赖 server，恶意中继扣留撤销时的租约窗口仍见 [scope §4](scope.md#4-信任边界)，直连不消除该限制。

需要新增传输分片、连接代次、ACK/恢复、barrier 及加密信令/控制消息。上线这些约定时协调提升 Go `internal/protocol`、网页 `web/src/protocol.ts`、Android `core/Version.kt`、iOS `RACore/Version.swift` 四处同值协议号；具体号随实现基线确定，本次文档不改协议。后续各期改变约定时继续按 [architecture §4](architecture.md#4-协议设计要点) 判断升级，不写旧协议降级或推断分支。各期独立发布、可关闭直连只指**同一当前协议**的运行时开关，不表示新旧协议互通；需要一起升级或重建数据的要求写入发布说明。

## 6. STUN 与诊断

自建 STUN 只发现映射，不授权业务；单独提供 IPv4/IPv6 UDP 入口，HTTPS 反向代理不能自动承载它。不做 TURN、端口预测或扫描。STUN 使用小响应、源地址内存短期限流及全局预算防反射放大，关闭持久 IP access log。生产入口和容量仍需确认，见 [计划](plan.md#传输模块与直连)。

日志不记录 IP、端口候选串、SDP、ICE 凭据、指纹全文、原始 ICE 错误对象、内容或密钥；接管/关闭 Pion 和 libwebrtc 默认调试输出。可在本机滚动聚合候选类型、地址族、路径字节数、RTT p50/p95、吞吐、队列峰值、建连耗时、回退原因、unknown、重放/快照次数和 ICE CPU 耗时；有容量上限、不上传。信任域新增暴露以 [scope §4](scope.md#4-信任边界) 为准。

## 7. 界面规则

界面只订阅 Link 的只读状态；显示当前交互主路径及其 RTT，bulk 是否使用 direct 另在检查页说明，热备的 relay 副本不把主路径写成中继。在线性与某条 socket 状态分开；单路 soft timeout 不能发布“电脑离线”。服务同步不可用仍单独按 [architecture · 断线](architecture.md#断线时显示什么) 提示，不能因 direct 可用假装历史已同步。

- 会话页副标题的电脑名前，直连时加 12 的 `bolt.horizontal` 类图标，颜色 `ink2`；中继无图标。点副标题显示菜单式气泡：第一行是路径及 RTT（例如“直连 · 12 ms”/“经中继 · 180 ms”）；第二行 13 号 `ink2` 写“手机和电脑直接通信”或“经中继服务器转发”；尝试直连后仅在说明中附“当前网络不支持直连”或“正在尝试直连…”等可证实的进展/原因，不加加载圈。
- 设置 › 电脑 › 电脑详情的标题下写“在线 · 直连”/“在线 · 经中继”；电脑状态页标题下的实时状态同样附路径与 RTT（如“● 实时 · 直连 12 ms”）。
- 连接检查页新增“到这台电脑的路径”：主路径、RTT、各用途路径、直连可用性与可证实原因、最近切换时间。局域网/IPv6/打洞类型可作详情；不能仅因 ICE 超时就断言“对称 NAT”，无法判明时说明当前网络未能直连。
- 路径切换只以 200 ms 淡入淡出更新图标和文字，不 toast、不震动、不出横幅。可见的气泡或页面每 5 秒更新 RTT；仅为显示时延的测量随可见性停止，Router 的前台活性探测另按第 3 节执行。
- 设置 › 电脑提供本机“尽量直连”开关，默认开；关闭后本机只走 relay，不发 STUN/ICE，任一对端关闭即不建立 direct。说明为“直连更快，内容同样端到端加密。直连时对方设备能看到你的 IP 地址，中继看不到通信内容。”性能收益受第 3 节的升级条件约束。

以上文字和时延是设计示例。实施时按语言契约写入 `i18n/messages/<domain>.json`，生成各端包装器；不在产品中硬编码。界面稿更新单独排在 [计划](plan.md#传输模块与直连)，本次不改 HTML。
