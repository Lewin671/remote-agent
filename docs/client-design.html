切到完全放行？

之后所有操作都不会再问你，手机上也收不到审批。只对这个会话生效。

取消
切换
切到完全放行前二次确认，chip 变红

只保留两边都有的 4 种（实测：codex-cli 0.157.1、Claude Code 2.1.284，2026-09-29）

客户端CodexClaude Code
询问Ask for approval（/permissions）manual
自动Approve for me（auto_review）auto
计划Plan mode（Shift+Tab，和权限独立）plan
完全放行Full Accessbypass（启动时没允许的会话置灰）
不提供—accept edits

设计取舍

  • 只做共有的：模式 4 种，审批卡片只有「允许 / 拒绝」，拒绝时可以附一句说明（两边的 hook 都支持）。「总是允许」「允许并切到 auto」这类只有一边有的选项不做，需要时去终端
  • 「询问」语义不完全一样：Codex 在工作区内改文件、跑命令本来就不问，只有联网和越界才问；Claude Code manual 每一步都问。客户端不抹平，按 CLI 实际发来的审批请求显示
  • 「自动」下手机不弹审批卡：hook 不表态，交给 CLI 自己判断；它拒绝的，模型在对话里请求批准，你直接回复（Codex 已实测先 hook 后 auto_review，见 plan.md）
  • Codex 的计划：计划模式和权限是两个开关。选「计划」只打开计划模式、权限不变；选其他三种会关掉计划模式再切权限
  • 模式以 CLI 为准：客户端只发「切换」指令，显示的是从 rollout / transcript / 屏幕读回来的结果；在电脑终端里切的，聊天里记一条。终端里切到了不在这 4 种里的模式（如 accept edits），chip 照实显示
  • 切到完全放行要二次确认，新会话默认值沿用 CLI 自己的配置

待实测 / 待确认

  • Claude Code 在 auto 模式下，PermissionRequest hook 是只收到分类器拦下的请求，还是全部请求
  • 计划结束时的交互：Claude Code 的 ExitPlanMode 能不能走 hook；Codex 计划模式怎么结束
  • 运行中能不能切：Codex 的 /permissions、Claude Code 的 Shift+Tab 都只在空闲时验证过
  • 要不要允许在手机上切到完全放行（目前设计是允许，但要二次确认）
