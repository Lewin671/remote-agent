# 界面设计规范

本文写客户端界面（网页、宽屏、Android 和 iOS）共用的视觉与交互规则：信息层级、颜色、字号、间距、圆角、图标、组件、对话正文的排版和文案，以及每条规则的理由。界面具体长什么样见当前界面稿 [design/client-v48.html](design/client-v48.html)，功能边界见 [scope.md](scope.md)，技术决策见 [architecture.md](architecture.md)。本文不写某个画面的布局；界面稿和本文冲突时，先按本文改界面稿，确实需要例外的，在本文写明例外和理由。

## 1. 信息层级

每个画面只有三层，按下面的顺序分配视觉重量：

| 层级 | 是什么 | 视觉手段 |
|---|---|---|
| 1 内容 | 对话正文、会话标题、用户正在写的消息 | 主文字色 `fg`、15 号或更大；不加底色和边框 |
| 2 需要你 | 等你处理的审批、提问、计划、弹窗，以及发送和允许这类主操作 | 橙色只用在状态点和类型词上；主操作用唯一的蓝色实心按钮 |
| 3 其余 | 元信息（CLI、机器、时间、计数）、次要入口、说明文字 | `muted` 色、12–13 号；不用粗体、不用彩色底 |

由此得出几条硬规则：

- **一屏最多一个实心按钮**，它就是这屏最该做的事。审批卡片里「允许」是实心，「不允许」不是；输入框里的发送是实心，其余都不是
- **说明不重复标题**：分组标题已经说明的属性，不在每一行再写一遍，例如「常用项目」下不再给每个项目加「常用」标记；会话行里只写这个范围里不止一种的属性，例如只有一个项目时不写项目名（[architecture §8](architecture.md#主页的范围)）
- **罕见状态不占主操作的位置**：像「这个项目已从列表移除」这样的状态，用提示条加一个文字操作，不用整宽实心按钮
- **同一种东西只有一种画法**：项目在范围菜单、选项目和项目管理里是同一个列表、同一种行（第 6 节「项目行」），对它能做的操作在各处同名同序；新加一处列出项目的地方，用现成的组件，不另画一种
- **计时、计数和超时提示是元信息**，用 `muted`；只有已经进入最后阶段（比如审批剩不到 1 分钟）才升级为橙色
- **次要能力收进二级**：模型、模式、上下文、机器在「⋯」里；常驻界面只放能改变当前决策的信息

## 2. 颜色

颜色只表达状态和可操作性，不做装饰。亮暗两套取值见界面稿开头的 `:root` 与 `[data-theme="dark"]`，正文对比度不低于 4.5:1。

| Token | 用途 | 不要用于 |
|---|---|---|
| `bg` / `card` / `soft` | 页面底 / 卡片与列表 / 次级表面（输入框、代码块、提示条） | — |
| `chip` / `track` | 次按钮、标签和行内代码的底 / 进度槽、引用左边的竖条 | — |
| `fg` / `fg2` / `muted` / `faint` | 正文 / 次级正文与代码 / 元信息和说明 / 箭头与分隔符号 | `faint` 不用于任何需要读的文字 |
| `line` | 1px 分隔线与描边 | 粗于 1px 的边框 |
| `blue`（文字）/ `blue-bg`（实心） | 可点击的文字与链接、选中项、运行中、唯一的主操作 | 纯装饰、标签 |
| `orange` / `orange-ink` | 需要你处理：状态点、类型词、临近耗尽的额度 | 按钮底色、大面积底色 |
| `green` / `green-ink` | 空闲、在线、成功 | 按钮 |
| `red` / `red-bg` | 失败、会丢数据或不可撤回的操作、拒绝与中断 | 普通提示 |
| `gray` | 已结束、离线、未知 | — |

- 同一种含义在所有画面用同一个颜色：「中断」「拒绝」一律红字，「重试」「恢复」一律蓝字
- 状态不只靠颜色：状态点旁边总写状态词
- **红色实心按钮只用在确认对话框**里的删除、移除、退出、结束、切到完全放行；普通页面上的「拒绝」「发送理由并拒绝」用灰底红字
- 对话框标题一律用 `fg`，危险由按钮表达，不把标题染红
- 提示条（banner）统一用 `soft` 底，只用文字颜色区分警告（`orange-ink`）和错误（`red`），不用彩色底块
- 项目头像颜色由项目名决定，同一项目在所有画面同色；同名项目同色也没关系，副标题里的路径负责区分
- 深色只给终端和图片查看器。终端之外的代码块、命令预览不用深色底，用比所在表面高一级的表面：在 `card` 上用 `soft`，在 `soft` 上用 `card`

## 3. 字号与字重

| 字号 | 用途 |
|---|---|
| 30 | 一级页面大标题（设置、加入账户，以及还没有项目时的「会话」） |
| 22 | 宽屏页面标题、手机主页的范围标题（项目名或「全部项目」）、上下文百分比等单个大数字、配对码输入 |
| 17 | 弹层和对话框标题、整页问题、回复里的一二级标题 |
| 15 | 正文、列表主行、按钮、输入框 |
| 13 | 列表第二行、提示条、链接式操作、分组标题 |
| 12 | 元信息、时间、说明文字、代码 |
| 11 | 只用于底部标签栏文字和图片角标 |

- 字重只用 400、500、600；700 只给头像字母和计数角标
- 代码、路径、命令用等宽 12 号（对话正文里的行内代码和路径用 13 号）；行内代码是带圆角的浅底小块，不是整行高的底色
- 配对码这类需要逐位核对的数字可以用更大的等宽字，这是唯一的例外

**字体与平台字重**。设计稿按 Apple 设备的效果画：西文 SF Pro，中文苹方。苹方最粗只有 Semibold，所以 CSS 的 600 和 700 在中文上都显示为 Semibold。其他平台的中文来自 Noto Sans CJK 等字体，同一标称字重下明显更重（2026-09-30 在 API 36 模拟器上和设计稿同倍率对比过），因此：

| 设计稿字重 | Apple 设备 | Android 与其他平台的中文 | 其他平台的西文 |
|---|---|---|---|
| 400 | 400 | 400 | Inter Regular |
| 500 | 500 | 450 | Inter Medium |
| 600 | 600 | 500 | Inter SemiBold |
| 700 | 700 | 600 | Inter Bold |

- Apple 设备只调用系统自带的 SF Pro、苹方和 SF Mono，不打包也不引用它们的文件
- 其他平台的西文和数字用 Inter，代码、路径和命令用 JetBrains Mono；中文仍由系统字体回退。实现方式是把各个 Inter 字重登记在下调后的字重上，西文保持标称字重，只有中文随请求降一档：网页见 `web/src/styles.css`，Android 见 `Theme.kt` 的 `platformWeight`

打包的字体只用允许再分发的开源许可，并随附许可证原文：

| 字体 | 用途 | 来源 | 许可 | 许可证位置 |
|---|---|---|---|---|
| Inter 4.1（西文子集） | 其他平台的界面西文和数字 | github.com/rsms/inter | SIL OFL 1.1 | Android `res/raw/ofl_inter.txt`（设置 › 开源许可）；网页 `/fonts/OFL-Inter.txt` |
| JetBrains Mono 2.304 | 代码、路径和命令；Android 终端 | github.com/JetBrains/JetBrainsMono | SIL OFL 1.1 | Android `res/raw/ofl_jetbrains_mono.txt`；网页 `/fonts/OFL-JetBrainsMono.txt` |
| Sarasa Fixed SC 1.0.42（符号子集，裁剪方式见 Android `assets/fonts/README.txt`） | Android 终端里 JetBrains Mono 没有的符号 | github.com/be5invis/Sarasa-Gothic | SIL OFL 1.1 | Android `res/raw/ofl_sarasa_gothic.txt` |

## 4. 间距、圆角与阴影

- 手机正文左右留 16，停靠区、输入框和状态卡左右留 10–12；宽屏正文最宽 760
- 间距取 4 的倍数：4 / 8 / 12 / 16 / 24
- 可点区域不小于 44×44，图标本身可以更小，由外层补足

| 圆角 | 值 | 用于 |
|---|---|---|
| — | 4 | 行内代码 |
| `r-xs` | 6 | 代码块、工具输出、图片角标 |
| `r-sm` | 10 | 按钮、输入字段、选项、提示条、小卡片 |
| `r-md` | 14 | 分组列表、卡片、上下文框 |
| `r-lg` | 20 | 底部弹层、对话框 |
| 胶囊 | 高度的一半 | 输入框、标签、队列条目、圆形按钮 |

- 阴影只给浮在内容上的东西：弹层、对话框、弹出菜单、「↓ 新消息」。卡片和停靠区不用阴影，用 `line` 分隔
- 不用彩色描边强调卡片；选中项用 `blue-soft` 底加 1px `blue` 描边

## 5. 图标

图标全部取自 [Lucide](https://lucide.dev)（ISC 许可），不用系统字体里的符号字符，也不混用别的图标库：字符的粗细、大小和基线随平台字体变，同一个界面里对不齐。网页用 `lucide-react`，只打包用到的图标，统一从 `web/src/icons.tsx` 引入；Android 把同名图标的路径写成 `ImageVector`，放在 `ui/Icons.kt`，不引入图标库依赖；iOS 同样把路径写在 `UI/Kit/Icons.swift`。

| 图标（Lucide 名） | 含义 | 位置 |
|---|---|---|
| `chevron-right` | 进入新页面或弹层 | 文字或行的末尾 |
| `chevron-left` | 返回上一页、上一级目录 | 导航栏左侧、目录列表第一行 |
| `chevron-down` / `chevron-up` | 就地展开 / 收起，或打开贴着它的菜单 | 文字末尾，如「处理」「收起」、主页的范围标题 |
| `ellipsis` | 更多操作 | 导航栏右侧、行末 |
| `plus` | 往消息里添加（图片）；列表末尾的「添加设备」「新项目」 | 输入框左侧、操作行行首；新建会话不用它 |
| `square-pen` | 新建会话 | 手机主页大标题右侧、宽屏侧栏标题右侧；纯图标、`blue`、无底，悬停提示「新会话」 |
| `arrow-up` | 发送 | 输入框右侧的实心圆按钮 |
| `square`（实心） | 中断这一轮 | 运行中输入框空着时，占发送按钮的位置 |
| `arrow-down` | 回到最新消息 | 「N 条新消息」前 |
| `check` / `x` / `loader-circle` | 完成 / 失败 / 进行中 | 工具行行首、提示条和状态文字前；`check` 也标出选中项，`x` 也用于关闭和清空 |
| `copy` | 复制这段代码 | 回复里代码块的右上角；复制后换成 `check`，失败换成 `x`，约 1.5 秒后变回 |
| `square` / `square-check` | 任务列表里没做完 / 做完的一项 | 回复里任务列表的行首，代替圆点 |
| `minus` | 已取消 | 工具行行首 |
| `search` | 筛选 | 筛选框左侧 |
| `message-square` / `settings` | 会话 / 设置 | 底部标签栏、宽屏侧栏底部 |
| `laptop` | 一台电脑 | 设备列表行首的色块里 |
| `globe` | 浏览器客户端 | 设置里客户端行行首的色块里，和电脑行同样画法 |
| `smartphone` | 手机 App | 同上 |
| `tablet` | iPad | 同上 |
| `wifi-off` / `cloud-off` | 本机网络不通 / 连不上服务器 | 导航栏下的连接提示条 |
| `arrow-left` `arrow-up` `arrow-down` `arrow-right` `corner-down-left` | 方向键和回车 | 终端的按键栏 |
| `keyboard` | 调出屏幕键盘 | 终端按键栏的「键盘」前 |
| `maximize-2` | 让终端适配这块屏幕 | 终端工具条的「适配」前 |

- 同一个意思只用一个图标；要加新图标时先在 Lucide 里找，并在上表补一行
- 本文其他小节为了简短，用字符指代上表的图标：`›` 是 `chevron-right`（向下、向上的 `›` 是 `chevron-down` / `chevron-up`），`⋯` 是 `ellipsis`，`＋` 是 `plus`，`■` 是实心的 `square`，`✓` `✕` `◌` 是 `check` `x` `loader-circle`，`⌕` 是 `search`
- 画法不改：24 网格、线宽 2、圆头圆角，颜色跟随所在文字（`currentColor`）。只有中断的 `square` 填实，任务列表里的 `square` 不填
- 大小跟随旁边的文字：行内图标和文字同高（1em 左右），单独成按钮的图标 20–22，标签栏 22；可点区域仍不小于 44×44，由外层补足
- `loader-circle` 匀速旋转，一圈约 0.9 秒；系统要求减少动态效果时不转
- 纯图标按钮必须带文字标签（`aria-label` / `contentDescription`）；紧挨着文字、只起装饰作用的图标对读屏隐藏
- 状态点不是图标，是画出来的实心圆，旁边总写状态词
- 文案里的路径写法（如「设置 › 设备」）和快捷键（如「⌘K」）是文字，不换成图标

**应用图标**：各端是同一个标记，一个终端提示符 `>` 加下划线光标。底是白到 `#E9EBF0` 的竖向渐变，提示符用墨色 `#1D1D1F`，光标用橙色 `#F5820A`，取「需要你」的意思。浅底在一排蓝色、深色的开发工具图标里好认。网页和 iOS 的位图由 `scripts/gen-icons.swift` 画出，改图标时改这个脚本再重新生成；Android 的启动图标和通知小图标是同一组坐标的矢量（`res/drawable`），iOS 界面里用到标记的地方是 `AppMark`。带透明圆角的网页图标描一圈细边，免得在浅色页面上看不出轮廓；标签页图标里的标记放大到 1.3 倍，16px 下才看得清。
- 许可证原文随附：Android 在 `res/raw/isc_lucide.txt`（设置 › 开源许可），网页在 `/licenses/ISC-Lucide.txt`，iOS 在 `Resources/Licenses/ISC-Lucide.txt`（设置 › 开源许可）

## 6. 组件

**按钮**

| 类型 | 样式 | 用于 |
|---|---|---|
| 主按钮 | `blue-bg` 实心、白字 | 这屏唯一的主操作：允许、发送、加入、恢复会话 |
| 次按钮 | `chip` 底、`fg` 字（在灰底卡片里用 `card` 底） | 取消、再试一次、去终端 |
| 否定按钮 | 次按钮的底、`red` 字 | 拒绝、发送理由并拒绝 |
| 危险按钮 | `red-bg` 实心、白字 | 只在确认对话框里 |
| 文字操作 | `blue` 字、无底，行尾对齐；整宽时居中，高 44；危险时 `red` 字 | 重试、撤销、查看；⋯ 菜单里的「中断」；更新弹层里主按钮下面的「检查更新」 |

按钮文字 15 号、600；禁用时整体 40% 不透明度，不换颜色。发送按钮与其他主按钮同色，没有内容时同样按禁用显示。

**设备行**（设置页）：电脑和客户端都以 `ico` 色块图标开头（电脑 `laptop`，浏览器 `globe`，手机 `smartphone`，平板 `tablet`），然后是名字；电脑的状态（「● 在线」「2 小时前」）总在行尾右侧，不挪到名字旁边，有额度时额度作为名字下面的第二行。

**列表行**：主行 15 号，第二行 13 号 `muted`，第三行 12 号元信息；行间用 1px `line`，从文字起点开始画。导航行末尾放 `›`，操作行（如「清理查看缓存」「重新读取」）用蓝字、不放 `›`，危险操作用红字。

**会话行**：进行中和需要处理的会话，第一行标题（右边时间），第二行状态词加预览，第三行只写范围内不止一种的项目、CLI、机器，依次用「 · 」隔开，分叉出的会话在最前面写「分叉」；都没有就只有两行。已结束的会话只占一行：标题，右边时间（全部项目里是「项目 · 时间」），不带状态点，由日期分组标题说明它们已经结束。时间在今天和昨天的分组里写时刻，近 7 天写星期，更早写日期。

**项目行**：项目头像、名字（15 号 600），第二行 12 号 `muted` 写路径和会话数，和主页的「需要处理」「进行中」同一口径（「~/Code/foo · 1 个待处理 · 3 个进行中」），为 0 的部分不写，都为 0 时它的电脑都不在线就写「电脑不在线」，否则只写路径；范围菜单里「全部项目」一行同样计数，都为 0 时写项目个数；行间 1px `line`，行高不小于 52。列表先「常用」后「其他」，只有一组时不写分组标题；超过 8 个时顶部有搜索；最后一行是蓝字的「＋ 新项目…」，`＋` 占头像的位置。行尾按所在的地方放一样东西：范围菜单是当前范围的 `✓`，选项目是 `›`，项目管理是 `⋯`（常用和移除）。移除要确认，对话框里是红色实心的「移除」，没有撤销。

**范围标题**：主页和宽屏侧栏的标题是当前范围，项目头像加项目名，或「全」字灰底头像加「全部项目」，末尾是向下的 `›`；点开是范围菜单（手机是底部弹层，宽屏是贴着标题的弹出菜单），当前范围行末打 `✓`。还没有项目时标题是不能点的「会话」。

**筛选框**：胶囊形、`chip` 底，左边 `⌕`，占位文字「按标题筛选」；有内容时右边是 `✕`。宽屏占位右边写快捷键。

**分组标题**：13 号 600 `muted`；右侧可以放计数（400）或一个文字操作（蓝字 + `›`）。

**提示条**：`soft` 底、`r-sm`、13 号，左边说明、右边最多一个文字操作。用于连接状态、推送未开、保存失败、罕见的页面状态。

**连接提示条**：导航栏下通栏一条，`soft` 底、12 号 `muted`，只在没连着服务器时出现。按离本机最近的一段故障写一句，各带一个图标：`wifi-off`「本机网络不通 · 显示的是上次的内容」、`loader-circle`「正在重连…」、`cloud-off`「连不上服务器 · 正在重试」，最后一种右边有「详情」。没有缓存可看时，连不上服务器用 `red` 并直接写原因。提示条说过的事不在别处再说一遍：这时没结束的会话都是灰点加「未连接」，不出「××× 不在线」状态卡，读取失败也不出红条。哪种情况算哪一段见 [architecture · 断线时显示什么](architecture.md#断线时显示什么)，画面见 [client-v48 · 断线](design/client-v48.html#link)。

**等待事项（停靠区）**：进会话时，审批、提问、计划、终端弹窗、图片确认等要你处理的事默认展开：来这个会话多半就是为了处理它。展开后只有一行头部「● 类型　元信息　收起」，元信息是「还有 N 项 · 剩 X 分钟」这类，只写剩多少时间，不加「，超时拒绝」（这句留给首页审批卡），计划的「展开全文 ›」放在「收起」前面；摘要只在收起时显示，不在内容里再写一遍标题。内容区最高约占会话内容区可视高度的 60%（至少 240，且给输入框和一点聊天留出位置），超出时内容区自己滚动，操作按钮固定在下面；命令和计划正文不单独限高，跟着内容区滚动。点「收起」后这一项是一行「● 类型 · 摘要 · 处理」，末尾是向下的箭头，按事项 ID 记住，换成新的一项又默认展开。输入框里有没发出的草稿（文字或图片）时新来的一项也只留这一行，免得把正在写的消息挤开；输入框只是有焦点不算，电脑上发完消息焦点一直留在输入框里。会话内容区太矮放不下时也只留这一行，点它进整页。只有状态点用橙色。多项时只停靠优先级最高的一项。

**输入框**：胶囊形，左「＋」、中正文、右发送；正文从一行起步，最多约六行。「＋」只做一件事：点一下直接选图片，不弹菜单；例外是 iOS 上剪贴板里有图片时先问「相册」还是「粘贴」，因为系统的输入框不接受粘贴图片，没有别的入口。模式、模型、上下文不常驻，放在导航栏的 ⋯ 菜单里，上下文占用高时在 ⋯ 上加橙点。输入框里不加提示行，胶囊始终一行起步：审批模式写在会话导航栏第二行的状态后面，完全放行用红字，读不到（包括启动中 CLI 还没报出）时不写，新建时写在项目设置摘要里，读不到时写「跟随 CLI 设置」，不出现「未读到」。占位文字里的快捷键按平台写：Mac（及其他 Apple 设备接键盘时）写「⌘↵」，其他写「Ctrl+Enter」，触屏设备（主指针不是精确指针）不写快捷键，如「消息 · ⌘↵ 发送」「描述任务，Ctrl+Enter 开始」。新会话用的设置写成项目标题下的一行摘要按钮：`chip` 底、`fg2` 字、末尾 `›`，宽度随内容，其中只有完全放行用红字；点开是项目设置；摘要以选中的 CLI 开头，后面依次只写审批模式、机器和模型；推理强度和上下文窗口不写进摘要，在项目设置里看；机器只在账户里不止一台时才写。一行放不下时先省略机器名（至少留 3 个字），模式和模型最后才省略；Android 上摘要可以折成两行，机器名超过 16 个字时截到 16 个字。新建输入框旁有一个 CLI 的分段按钮，只列这台机器装了的，只有一个时不出现：手机在输入框上方单独一行（键盘弹出时仍在；键盘只让列表变矮，画面不增删内容，免得跟着键盘动画跳动，项目标题和摘要滚出屏幕后才收进导航栏第二行），宽屏在输入框下方、和摘要同一行，两者同高，摘要紧挨着切换时不再重复写 CLI 名。CLI 常驻而模型、审批不常驻，是因为每个任务都可能换 CLI（[architecture §13](architecture.md#13-daemon-设置与远程新建会话)）。输入框右侧只有一个按钮：运行中且输入框空着时是 `chip` 底圆形 `■` 中断，打字后变回发送；运行中点发送是插入这一轮，长按选「这一轮结束后再发」，有草稿时中断走 ⋯ 菜单；输入框上方不放排队数量、中断或工具摘要这样的独立一行。排队的消息作为待发气泡留在对话末尾（`card` 底、细边框，下面一行写等什么和「取消」），不另开队列页；新会话启动中的第一句话也是待发气泡，只出现这一次；正文最多 4 行，点开看全文，说明行只占一行，放不下时省略说明、保留操作。说明只用几种说法：「插入这一轮」「这一轮结束后发」「等 <CLI> 就绪后发出」（新会话的第一句），以及「已暂停」「正在取消…」「取消没成功，仍在排队」这类少数状态；不加「排队 ·」「已送达电脑 ·」前缀，也不加「等输入框就绪」这类过程；排着不止一条时后面加「 · 第 N 条」，别的客户端排的再加它的名字。发送失败的消息只分两类，原因写短，不加「不会自动重发」这类附加说明：确定没发出去的（会话已结束、CLI 没认出图片、电脑明确拒绝）红字「没发出去：<原因>」，配「重试」「放回输入框」中可用的；不确定发没发出去的（已送到终端但没确认、读不到终端输入框、连接超时）橙字「可能没发出去：<原因>」，连接中途断开时原因统一为「连接中途断了」，配原来的操作（去终端、重试、移除此提示）。

**终端按键栏**：终端下面的 Esc、方向键、Tab、Ctrl+C 和「键盘」按键栏是给触屏用的；网页宽屏上主指针是精确指针（`(pointer: fine)`，鼠标或触控板）时不显示，直接用键盘；触屏照旧显示。Android、iOS 不变。

**视图切换**：聊天 / 终端 / 并排这类切换，手机和宽屏都用下划线标签；手机上标签单独一行铺满，宽屏上放在会话标题行的右侧、⋯ 的左边，顶栏只有一行。选了哪个视图记在这台设备上，之后打开任何会话都是它；显示不了时（窗口放不下并排、会话已结束或电脑离线）临时显示聊天，不改记住的值；新建会话后自动进终端不算选择。分段按钮（灰底胶囊）只用于同一设置的多个取值，如推理强度、外观的自动 / 亮色 / 暗色。宽屏上设置类页面（设置、设备、电脑、客户端、额度）的内容限制在约 640 宽的居中一列，不随窗口拉满；Android 在平板和横屏上同样处理。

**弹层与对话框**：弹层顶部有抓手，标题 17 号；只有需要确认提交时右上角才放「完成」或「取消」。⋯ 菜单（会话、项目管理）和选项目是同一种左对齐列表弹层：顶部一行粗体写它是关于什么的（会话是「CLI · 项目 · 机器」，下一行等宽写目录），下面每个操作一行，行间 1px `line`；设置类的一项写成「名称 …… 值 ›」（值在行尾，`fg2`，完全放行红字、上下文高时橙字），普通操作是 `fg` 字的普通行，中断、结束、移除这类是红字行；不用居中的按钮，也没有单独的「取消」卡片，点遮罩或抓手关闭。宽屏上同样是这个弹层，居中显示。更新弹层里，「检查更新」作为文字操作放在主按钮下方。对话框标题 17 号 `fg`，说明 13 号，按钮左「取消」右确认。

**代码块**：等宽 12 号、`r-xs`、表面规则见第 2 节。停靠区里的不单独限高，跟着内容区滚动；首页审批卡里的见下面「审批」；回复里的见[第 7 节](#7-对话正文)。

**审批**：先给要执行的内容，再给说明：头部 → 命令块 → 说明 → 按钮，停靠区、审批整页和首页审批卡都是这个顺序。首页审批卡的命令块最多显示 6 行，按整行截断，不切在半行，截断时第 6 行末尾是「…」，也不在卡片里嵌套滚动；超过 6 行时块下面一行 13 号 `blue`「还有 N 行 · 展开」（N 按屏幕上折出来的行数算，末尾向下的 `›`），点了就地展开全文，再点「收起」；说明最多 2 行，放不下省略。「不允许」（红字）和「允许」（实心）并排；永久授权在原生终端处理，客户端支持边界见 [architecture §7](architecture.md#7-审批)。点「不允许」就地出现输入框，写一句说明或留空再确认。提交后整张卡锁住，只留一行状态；没送到时「重试」重发同一个选择。宽屏（网页 ≥900 宽，Android、iOS 的平板宽度）上审批和计划的按钮行不撑满，整行最宽 480，靠左对齐内容。

**添加设备**：当前管理端（网页、Android 或 iOS Client）能添加和移除其他设备（协议 10，[architecture · 配对](architecture.md#配对)）。三端都在设置的电脑组和设备页放「添加设备」，在管理端的无电脑空状态保留说明与按钮。非管理端在同一位置指向当前管理端的名字，措辞见第 8 节；Machine 不显示管理或接任入口。移除设备保留电脑档案；从档案「重新加入并接续会话」，永久删除记录另行确认。

**会话导航栏**：第一行只放会话标题，第二行写状态和审批模式，如「运行中 · 询问」「空闲 · 自动」「计划待批准 · 计划」；只有完全放行用红字，其余灰字；读不到审批模式时（包括启动中）只写状态，不写「CLI 配置（未读到）」这类话；已结束的会话只写状态。CLI、项目、机器和目录放在 ⋯ 菜单顶部，不占导航栏，会话 ID 不显示；菜单（画法见「弹层与对话框」）里依次是审批模式、模型、上下文，然后是重命名、分叉会话、中断和结束会话；Android、iOS 在重命名前多一行「项目设置」，是普通行，网页没有。已结束的会话只剩重命名和分叉会话（原生端保留项目设置），电脑离线时菜单里只有顶部的信息（原生端保留项目设置）。暂时做不了的一项不藏起来：文字按禁用显示，下面一行 12 号 `muted` 写什么时候可以；点了以后要等结果的一项就地写进度，失败原因用红字写在它下面，菜单不关。

**工具调用**：一次调用一行，行首 `◌` / `✓` / `✕`，后面是等宽的命令，行尾写「已运行 4:15」、退出码或「后台运行」；两轮之间的分隔线上写「本轮用时 4 分 12 秒」，计时总说清是什么的时间；连续完成的折成「运行了 N 条命令」，点开只列命令。不显示输出，不做详情页，不放跳转终端的入口。

**长内容、大量内容与大字号**：界面稿里的文字都是短示例，实现要按下面处理，不靠示例长度撑住布局。

- 字多：标题、元信息、摘要一行放不下就省略，高风险词（如完全放行）放在前面，不会被省略掉；路径、命令、代码可以在任意位置换行，不撑出屏幕；消息正文完整显示，待发气泡最多 4 行、点开看全文
- 内容多：列表都有上限和「还有 N 个」入口。手机主页需要处理最多 3 张卡，进行中最多 5 个；宽屏侧栏（网页 ≥900 宽、平板）这两组不截断、不出「还有 N 个」，和已结束的一起整列滚动；已结束的先列 30 个、滚到底再加载，排队超过 3 条只显示前 2 条；项目超过 8 个时选项目弹层和范围菜单带搜索，范围内会话超过 8 个时主页带筛选框；聊天往上翻时分段读取更早的记录，读到开头时最上面是一行不带横线的「开始时间 · 目录」（不是当天的写出日期），带横线的分隔只用在两轮之间、分叉处和会话结束处；连续的工具调用、多张图都折叠
- 字号大：跟随系统字号，至少验证到 200%。行高随内容增长，不写死高度；左右两项放不下时右项换到下一行靠右，不压缩成一字一行；导航栏标题始终一行，放不下就省略；按钮文字可以换行，点击区不小于 44×44

## 7. 对话正文

agent 回复里的 Markdown。回复是手机上一列窄文字里的一句回答，不是一篇文档：结构靠留白分出来，不靠放大字号、描边和底色。

三端各有一个解析器，读法由共用的样例 `testdata/markdown/cases.json` 约束：网页的 `markdown.cases.test.ts`、Android 的 `MarkdownCasesTest.kt` 和 iOS 的 `RAMarkdownTests/CasesTests.swift` 都跑它，改读法先改样例。文字始终是文字，不当 HTML 插入。

**间距**：三档，相邻两块之间取下表里对得上的第一条。

| 位置 | 间距 |
|---|---|
| 回复的第一块之前 | 0 |
| 分隔线的位置 | 24 |
| 标题或加粗小标题紧跟在另一个标题后面 | 12 |
| 一二级标题之前 | 24 |
| 三级及以下标题、独占一行的加粗小标题之前 | 16 |
| 标题、加粗小标题之后 | 8 |
| 表格之后 | 16 |
| 段落后面紧跟列表 | 8 |
| 其余的块之间（段落、列表、代码块、表格、引用） | 12 |
| 列表项之间 | 4；列表里有一项会折行时，这个列表的各项之间 8 |
| 列表项和它的子列表之间 | 4 |
| 列表项里的段落、代码块、表格、引用之前 | 8 |

引用和列表项里面不分标题前后，块之间都是 12 和 8。

「会折行」按内容判断，不按当前屏幕实际折没折：一项里有换行，或显示出来的文字超过 40 个半角字符的宽度。宽度是估算：U+2E80 以后的字符（中文、日文、韩文、全角符号和大多数 emoji）算两个，其中半角片假名这类半角形式算一个，其余都算一个；差一两个字符只影响恰好卡在界线上的列表。项和行一样密时，几项折行的文字读起来像一整段；按内容判断，两端和不同宽度的窗口里同一个列表间距相同。

**各元素**

| 元素 | 画法 |
|---|---|
| 正文 | 15 号、行高 1.6、`fg`；过程中的说明（commentary）用 `fg2`。段内的单个换行保留 |
| 标题 | 一二级 17 / 600，三级 15 / 600，四级及以下 13 / 600 `muted`；行高 1.35。不画下划线 |
| 加粗小标题 | 整段只有一行加粗（可以带一个冒号）时，字不变，只按三级标题留白：CLI 常这样写小标题 |
| 加粗、斜体、删除线 | 600；斜体；删除线加 `muted` |
| 行内代码 | 等宽 13 号、`chip` 底、圆角 4、左右内边距 4；折行时每一段都有圆角。在一二级标题里用 15 号 |
| 链接 | 只有 http(s) 的目标能点，`blue`；裸写的网址也能点：到空白或句子自己的标点（全角标点、破折号、弯引号）为止，末尾的半角标点和没有配对的右括号不算进去。其他目标（多是本机路径）显示成等宽 13 号 `fg2`，不能点 |
| 列表 | 缩进 20，序号到两位数时这个列表缩进 28；圆点和序号用 `muted`，序号用等宽数字；第二层起用空心圆 |
| 任务列表 | 行首是 1em 的 `square` / `square-check`，`muted`；做完的整行 `muted`，不加删除线 |
| 代码块 | `soft` 底、不描边、`r-xs`、内边距 8 × 12、等宽 12 号行高 1.5、`fg2`；不换行，放不下时块内横向滚动。不加顶栏，不写语言名。右上角是 16 的 `copy` 图标，`muted`，可点区域 44；代码末尾留出图标的宽度，横向滚到头时没有字压在图标下面 |
| 长代码块 | 超过 16 行时只显示前 12 行，底部一行「展开全文」（13 号 600 `blue`，向下的 `›`），行尾 12 号 `muted` 写「共 N 行」；就地展开后是「收起」和向上的 `›`。按行数截，不按高度截 |
| diff | 写明 `diff` 或 `patch` 的代码块里，`+` 开头的行用 `green-ink`，`-` 开头的行用 `red`，其余不变 |
| 表格 | 只画行间 1px `line`，最后一行下面不画；不画竖线、外框和表头底色。表头 12 号 `muted` 不加粗、上方不留内边距，单元格 13 号行高 1.45、顶对齐；上下内边距 8，列间距 24，第一列从正文左边开始。宽度随内容，不拉满 |
| 表格的对齐 | 分隔行写了对齐就照它；没写时，一列里有内容的格子显示出来全是数量（数字带符号、货币或短单位，加粗和行内代码不影响）就右对齐并用等宽数字 |
| 宽表格 | 单元格最窄 34、最宽 240，超过就折行；整张放不下时横向滚动，手机上一直滚到屏幕边；右边还有内容时右缘 32 渐隐 |
| 引用 | 左边 2px `track` 竖条、内边距 12、文字 `fg2`；里面可以有段落、列表和代码块 |
| 分隔线 | 不画线，只留 24 的空白，回复开头的不留：带横线的分隔只用在两轮之间、分叉处和会话结束处（第 6 节） |

- **不做语法高亮**：颜色只表达状态和可操作性（第 2 节）。diff 的增删是这条的唯一例外，因为它是内容的含义，不是装饰
- **代码块不加「语言名 + 复制」顶栏**：那是聊天类产品的样式，语言名在手机上也没有用
- **回复里的长代码就地展开，不进整页**：对话本身就是一整页的滚动，展开后还能对着上下文读；停靠区里的命令也跟着内容区滚动，只有计划可以从「展开全文」进整页（整页里还有更多选项）
- 图片、HTML 标签、脚注、公式不渲染，按文字显示

## 8. 文案

- 写结果和下一步，不写实现：「MacBook 不在线，连上后才能恢复」，不写「连接失败 (ECONNREFUSED)」；原始错误放进「详情」
- 会话结束时先说原因：手动结束写「会话是被手动结束的。」；daemon 的详情以「the login shell」开头（客户端开的会话里登录 shell 没能启动 CLI，[architecture §6](architecture.md#6-接入-codex)）时写「电脑上的登录 shell 没能启动 CLI（原文）。请检查电脑上的 shell 配置，比如 ~/.zshrc。」，超时那条在括号后加「，可能卡在等待输入」；其余写「tmux 会话已经不在了。」这句三端逐字一致，改就一起改
- 说清是哪一段出了问题，并且只说知道的：本机没网时不写「电脑离线」，连不上服务器时不沿用断线前的「运行中」
- 按钮用动词，两到六个字；带省略号「…」表示还会再确认一次
- 时间窗口统一写「5 小时」「7 天」，不混用「本周」
- 同一个对象全局同名：电脑是会话执行的位置，在新建和会话设置里作为字段名时写「机器」；客户端是操作会话的入口；设备是两者的合称
- **设备的名字**：用户起的名字优先；没起名的客户端叫「平台 · 型号或系统」，取自它在设备元数据里自报的 platform 和 description：网页「Chrome · macOS」（浏览器 · 系统，读不出系统时只写浏览器，什么都没有写「浏览器」），Android「Android · <机型>」，iOS 写「iPhone」「iPad」，都读不出写「客户端」。只有账户里另一个客户端的默认名和它相同时，才在后面加「 · 」和设备 ID 后 4 位区分。不在首次打开时弹窗要求起名，改名在「设置 › 客户端」里
- **来源**：消息、系统行（如「Safari · iOS 将模式切到 计划」，名字和后文之间空一格）和工具行右侧的「已允许 · Android · Pixel 9」按同一套写法：本客户端做的不写来源，账户里有别的客户端也一样；电脑终端里输入的（daemon 记成本地，或客户端自己判断是在终端里输入的）一律写「<机器名> 终端」，不写「本地终端」；其他客户端写它的名字；设备列表还没读到时写「另一客户端」，列表读到了且查不到时才写「已移除的设备」，不写设备 ID；daemon 没记录来源的消息不写，审批、提问在别处处理了写「另一端」
- 数值和单位之间空一格，如「24 / 256 MiB」「2 分 12 秒」
- **配对说明**按实际流程写：当前管理端（网页、Android 或 iOS Client，只有一个）打开「设置 › 添加设备」，显示二维码和 8 位配对码；新设备扫码（Android、iOS）或输入配对码（网页只能输入）。不写「用手机扫这台设备的二维码」这种反方向的说法。统一称「管理端」「当前管理端」「接任设备」，具体设备写名字（如「管理端（Pixel 9）」），不用「管理端手机」「旧手机」「新手机」「管理端 App」。下面几句三端逐字一致，改就一起改：
  - 加入页（Android、iOS）：「在管理端打开「设置 › 添加设备」，扫它显示的二维码，或把 8 位配对码填在这里。」
  - 加入页（网页，不提扫码）：「在管理端打开「设置 › 添加设备」，把它显示的 8 位配对码填在这里。」
  - 非管理端且没有电脑的空状态：「还没有电脑。在管理端（<名字>）上打开「设置 › 添加设备」，把电脑加进来。」管理端保留一句说明和「添加设备」按钮。
  - 非管理端的设置/设备页：「要添加电脑或客户端，在管理端（<名字>）上打开「设置 › 添加设备」。」

- 未登录页的三个入口同名同序：「新建账户」「加入已有账户」「用恢复码找回管理权」。管理能力取决于验签状态中的 Client / AuthorityID，不取决于平台；Machine 不显示接任入口。
- 设置沿用 Android 的分组顺序：电脑（含添加设备）、客户端、账户安全；账户安全包含租约到期时间、恢复码（换码/否决）、交接管理权。管理端显示「现在续期」，其他成员显示「请打开 <管理端名称> 续期」。显示当前 head 已装证书的实际到期时间，不用当前时间加 72 小时替代。
- 恢复申请待处理时，首页和设置都保留醒目的处理入口和可生效时间；读取失败不能当作没有申请。网页安全通知独立于会话提醒，不承诺推送必达。
- 网页建账户/接任前固定提示：「此浏览器将是唯一管理端。清理网站数据或换浏览器会丢失管理密钥；恢复码必须离线保存。日常建议用 App 管理。」显式请求 `navigator.storage.persist()` 并显示真实结果，成功：「已请求浏览器保留数据」；失败：「浏览器没有承诺保留数据」。持久存储不保证用户清理数据后仍能恢复。
- iOS 建账户/接任前固定提示：「iOS 版没有后台安全提醒，建议每天打开一次，以免错过恢复申请。」
- 退出确认沿用 `authorityExitAdvice` 三句：有未核实操作：「安全操作结果尚未核实，请先继续原操作；退出会删除唯一完成材料。」唯一管理端：「此浏览器是唯一管理端，建议先交接；退出会删除管理密钥，没有恢复码备份将丢失管理权。」其他成员：「退出会删除本机密钥，需要重新配对。」原生端按平台改指代本机的词，不更改后果和顺序。
- CLI 核对图案提示：「先在这里确认，再在管理端上允许」。普通换码和交接 offer 必须先显示新恢复码并确认离线保存，再发布；存储失败时保留材料和错误，不显示成功。重启后继续原创建/紧急恢复草稿，不另建竞争状态；没有确认备份就完成原恢复时，进入账户立即引导换码。
