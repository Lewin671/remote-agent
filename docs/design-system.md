# 界面设计规范

本文写客户端界面（网页、宽屏和 Android）共用的视觉与交互规则：信息层级、颜色、字号、间距、圆角、符号、组件和文案，以及每条规则的理由。界面具体长什么样见最新界面稿 [design/client-v7.html](design/client-v7.html)，功能边界见 [scope.md](scope.md)，技术决策见 [architecture.md](architecture.md)。本文不写某个画面的布局；界面稿和本文冲突时，先按本文改界面稿，确实需要例外的，在本文写明例外和理由。

## 1. 信息层级

每个画面只有三层，按下面的顺序分配视觉重量：

| 层级 | 是什么 | 视觉手段 |
|---|---|---|
| 1 内容 | 对话正文、会话标题、用户正在写的消息 | 主文字色 `fg`、15 号或更大；不加底色和边框 |
| 2 需要你 | 等你处理的审批、提问、计划、弹窗，以及发送和允许这类主操作 | 橙色只用在状态点和类型词上；主操作用唯一的蓝色实心按钮 |
| 3 其余 | 元信息（CLI、机器、时间、计数）、次要入口、说明文字 | `muted` 色、12–13 号；不用粗体、不用彩色底 |

由此得出几条硬规则：

- **一屏最多一个实心按钮**，它就是这屏最该做的事。审批卡片里「允许」是实心，「拒绝」不是；输入框里的发送是实心，其余都不是
- **说明不重复标题**：分组标题已经说明的属性，不在每一行再写一遍，例如「常用项目」下不再给每个项目加「常用」标记
- **罕见状态不占主操作的位置**：像「这个项目已从列表移除」这样的状态，用提示条加一个文字操作，不用整宽实心按钮
- **计时、计数和超时提示是元信息**，用 `muted`；只有已经进入最后阶段（比如审批剩不到 1 分钟）才升级为橙色
- **次要能力收进二级**：模型、模式、上下文、机器在「＋」或「⋯」里；常驻界面只放能改变当前决策的信息

## 2. 颜色

颜色只表达状态和可操作性，不做装饰。亮暗两套取值见界面稿开头的 `:root` 与 `[data-theme="dark"]`，正文对比度不低于 4.5:1。

| Token | 用途 | 不要用于 |
|---|---|---|
| `bg` / `card` / `soft` | 页面底 / 卡片与列表 / 次级表面（输入框、代码块、提示条） | — |
| `fg` / `fg2` / `muted` / `faint` | 正文 / 次级正文与代码 / 元信息和说明 / 箭头与分隔符号 | `faint` 不用于任何需要读的文字 |
| `line` | 1px 分隔线与描边 | 粗于 1px 的边框 |
| `blue`（文字）/ `blue-bg`（实心） | 可点击的文字与链接、选中项、运行中、唯一的主操作 | 纯装饰、标签 |
| `orange` / `orange-ink` | 需要你处理：状态点、类型词、临近耗尽的额度 | 按钮底色、大面积底色 |
| `green` / `green-ink` | 空闲、在线、成功 | 按钮 |
| `red` / `red-bg` | 失败、会丢数据或不可撤回的操作、拒绝与中断 | 普通提示 |
| `gray` | 已结束、离线、未知 | — |

- 同一种含义在所有画面用同一个颜色：「中断」「拒绝」一律红字，「重试」「恢复」一律蓝字
- 状态不只靠颜色：状态点旁边总写状态词
- **红色实心按钮只用在确认对话框**里的删除、移除、退出、结束、切到完全放行；普通页面上的「拒绝」「发送理由并拒绝」用灰底红字
- 对话框标题一律用 `fg`，危险由按钮表达，不把标题染红
- 提示条（banner）统一用 `soft` 底，只用文字颜色区分警告（`orange-ink`）和错误（`red`），不用彩色底块
- 项目头像颜色由项目路径决定，同一项目在所有画面同色
- 深色只给终端和图片查看器。终端之外的代码块、命令预览不用深色底，用比所在表面高一级的表面：在 `card` 上用 `soft`，在 `soft` 上用 `card`

## 3. 字号与字重

| 字号 | 用途 |
|---|---|
| 30 | 一级页面大标题（会话、设置、加入账户） |
| 22 | 宽屏页面标题、上下文百分比等单个大数字、配对码输入 |
| 17 | 弹层和对话框标题、整页问题 |
| 15 | 正文、列表主行、按钮、输入框 |
| 13 | 列表第二行、提示条、链接式操作、分组标题 |
| 12 | 元信息、时间、说明文字、代码 |
| 11 | 只用于底部标签栏文字和图片角标 |

- 字重只用 400、500、600；700 只给头像字母和计数角标
- 代码、路径、命令用等宽 12 号（对话正文里的行内路径用 13 号）
- 配对码这类需要逐位核对的数字可以用更大的等宽字，这是唯一的例外

## 4. 间距、圆角与阴影

- 手机正文左右留 16，停靠区、输入框和状态卡左右留 10–12；宽屏正文最宽 760
- 间距取 4 的倍数：4 / 8 / 12 / 16 / 24
- 可点区域不小于 44×44，图标本身可以更小，由外层补足

| 圆角 | 值 | 用于 |
|---|---|---|
| `r-xs` | 6 | 代码块、工具输出、图片角标 |
| `r-sm` | 10 | 按钮、输入字段、选项、提示条、小卡片 |
| `r-md` | 14 | 分组列表、卡片、上下文框 |
| `r-lg` | 20 | 底部弹层、对话框 |
| 胶囊 | 高度的一半 | 输入框、标签、队列条目、圆形按钮 |

- 阴影只给浮在内容上的东西：弹层、对话框、弹出菜单、「↓ 新消息」。卡片和停靠区不用阴影，用 `line` 分隔
- 不用彩色描边强调卡片；选中项用 `blue-soft` 底加 1px `blue` 描边

## 5. 符号

| 符号 | 含义 | 位置 |
|---|---|---|
| `›` | 进入新页面或弹层 | 文字或行的末尾 |
| 向下 / 向上的 `›` | 就地展开 / 收起 | 文字末尾，如「处理」「收起」；由 `›` 旋转 90° 绘制，和导航箭头同一字形 |
| `▸` / `▾` | 树的折叠与展开 | 只用于宽屏侧栏的项目树，放在行首 |
| `⋯` | 更多操作 | 导航栏右侧、行末 |
| `＋` | 新建或添加 | — |
| `✓` / `✕` / `◌` | 完成 / 失败 / 进行中 | 工具行行首 |
| `●` | 状态点 | 状态词前 |

同一个意思只用一个符号。界面稿里标签栏的图标是占位，实现时用各平台的系统图标库，线条粗细统一。

## 6. 组件

**按钮**

| 类型 | 样式 | 用于 |
|---|---|---|
| 主按钮 | `blue-bg` 实心、白字 | 这屏唯一的主操作：允许、发送、加入、恢复会话 |
| 次按钮 | `chip` 底、`fg` 字（在灰底卡片里用 `card` 底） | 取消、再试一次、去终端 |
| 否定按钮 | 次按钮的底、`red` 字 | 拒绝、发送理由并拒绝 |
| 危险按钮 | `red-bg` 实心、白字 | 只在确认对话框里 |
| 文字操作 | `blue` 字、无底，行尾对齐；危险时 `red` 字 | 重试、撤销、查看、中断 |

按钮文字 15 号、600；禁用时整体 40% 不透明度，不换颜色。发送按钮与其他主按钮同色，没有内容时同样按禁用显示。

**列表行**：主行 15 号，第二行 13 号 `muted`，第三行 12 号元信息；行间用 1px `line`，从文字起点开始画。导航行末尾放 `›`，操作行（如「清理查看缓存」「重新读取」）用蓝字、不放 `›`，危险操作用红字。

**分组标题**：13 号 600 `muted`；右侧可以放计数（400）或一个文字操作（蓝字 + `›`）。

**提示条**：`soft` 底、`r-sm`、13 号，左边说明、右边最多一个文字操作。用于连接状态、推送未开、保存失败、罕见的页面状态。

**等待事项（停靠区）**：默认一行「● 类型 · 摘要 · 处理」，末尾是向下的箭头，只有状态点用橙色；展开后正文滚动、操作固定。多项时只停靠优先级最高的一项。

**输入框**：胶囊形，左「＋」、中正文、右发送；正文从一行起步，最多约六行。模式、模型、上下文不常驻，只在高风险时（完全放行）用一行红字提示，上下文占用高时在「＋」旁加橙点。

**视图切换**：聊天 / 终端 / 并排这类切换，手机和宽屏都用下划线标签；分段按钮（灰底胶囊）只用于同一设置的多个取值，如推理强度。

**弹层与对话框**：弹层顶部有抓手，标题 17 号；只有需要确认提交时右上角才放「完成」或「取消」。对话框标题 17 号 `fg`，说明 13 号，按钮左「取消」右确认。

**代码块**：等宽 12 号、`r-xs`、表面规则见第 2 节；超过高度时内部滚动，用「展开全文」进整页。

## 7. 文案

- 写结果和下一步，不写实现：「MacBook 不在线，连上后才能恢复」，不写「连接失败 (ECONNREFUSED)」；原始错误放进「详情」
- 按钮用动词，两到六个字；带省略号「…」表示还会再确认一次
- 时间窗口统一写「5 小时」「7 天」，不混用「本周」
- 同一个对象全局同名：电脑是会话执行的位置，在新建和会话设置里作为字段名时写「机器」；客户端是操作会话的入口；设备是两者的合称
- 数值和单位之间空一格，如「24 / 256 MiB」「2 分 12 秒」

## 8. 审查清单

新增或修改界面稿时逐条看：

- [ ] 每屏最多一个实心按钮，且它确实是这屏最该做的事
- [ ] 颜色只表达第 2 节里的含义，同一含义在各画面同色
- [ ] 分组标题说过的属性没有在行内重复
- [ ] 元信息都是 `muted`，没有加粗或上色
- [ ] 字号、圆角都在第 3、4 节的取值里
- [ ] 符号含义符合第 5 节，进入新页面和就地展开的箭头方向没有混用
- [ ] 终端之外没有深色代码块
- [ ] 亮色和暗色下都看过，可点区域不小于 44×44
