# 界面设计规范

本文写客户端界面（网页、宽屏、Android 和 iOS）共用的视觉与交互规则：信息层级、颜色、字号、间距、圆角、材质、图标、组件、对话正文的排版和文案，以及每条规则的理由。界面具体长什么样见当前界面稿 [design/client-v60.html](design/client-v60.html)，功能边界见 [scope.md](scope.md)，技术决策见 [architecture.md](architecture.md)。本文不写某个画面的布局；界面稿和本文冲突时，先按本文改界面稿，确实需要例外的，在本文写明例外和理由。

## 1. 信息层级

每个画面只有三层，按下面的顺序分配视觉重量：

| 层级 | 是什么 | 视觉手段 |
|---|---|---|
| 1 内容 | 对话正文、会话标题、用户正在写的消息 | `ink`、17 号或更大；不加底色和边框（你的消息是唯一带底的正文，用 `bubble`） |
| 2 需要你 | 等你处理的审批、提问、计划、弹窗，以及这屏最该做的事 | 等你处理的事用橙点和橙色类型词表达，最急的一件是深色卡；主操作是唯一的墨色实心按钮 |
| 3 其余 | 元信息（CLI、机器、时间、计数）、次要入口、说明文字 | `ink2`、13 号；不用粗体、不上色 |

由此得出几条硬规则：

- **一屏最多一个墨色实心按钮**，它就是这屏最该做的事：主页和定时页是右下角的「新任务」「新定时」，会话里是输入框的发送，状态卡里是「恢复会话」。深色卡（第 6 节「终端卡」）里的白色按钮（「允许」「批准」「提交」）另算：它在深色底上，和页面上的墨色按钮不会混淆。审批里「允许」是白色实心，「拒绝」不是
- **一句话说现在的情况**：主页和定时页的大标题直接说有几件事等你、有几个在运行、或者连不上，不让人从列表里自己数（第 6 节「大标题」）
- **状态都写出来**：行首的图形只帮你扫一眼，旁边总写状态词，格式「状态 · 内容」；状态词一律 `ink2`，不上色（第 2 节「状态图形」）
- **说明不重复标题**：分组标题已经说明的属性，不在每一行再写一遍，例如「常用项目」下不再给每个项目加「常用」标记；会话行里只写这个范围里不止一种的属性，例如只有一个项目时不写项目名（[architecture §8](architecture.md#主页的范围)）
- **罕见状态不占主操作的位置**：像「这个项目已从列表移除」这样的状态，用提示条加一个文字操作，不用整宽的墨色按钮
- **同一种东西只有一种画法**：项目在范围菜单、选项目和项目管理里是同一个列表、同一种行（第 6 节「项目行」），对它能做的操作在各处同名同序；等你批准的命令在主页、会话停靠区和宽屏是同一张深色卡。新加一处列出项目或等待事项的地方，用现成的组件，不另画一种
- **计时、计数和超时提示是元信息**，用 `ink2`；只有已经进入最后阶段（比如审批剩不到 1 分钟）才升级为橙色
- **次要能力收进二级**：模型、模式、上下文、机器在「⋯」里；常驻界面只放能改变当前决策的信息
- **各 CLI 一视同仁**：CLI 只写显示名（Codex、Claude Code、Antigravity），不加品牌色或图标；会话里的弹层标题直接写功能（「会话设置」「审批模式」），不加 CLI 前缀，会话属于哪个 CLI 写在 ⋯ 菜单顶部。CLI 之间的能力差异只有两种画法：这个 CLI 根本没有的功能不显示（不画一行永远灰着的「不支持」）；这个会话、模型或账户暂时用不了的保留原位、置灰，下面一行 13 号 `ink2` 写原因或什么时候可以。按 CLI 分组的设置（电脑的新项目默认设置）用顶部的分段控件切换，只列这台机器装了的，只装一个时不出分段；从新任务的摘要胶囊点开的项目设置只有句子里选中的那个 CLI 的一套，不出分段，装了不止一个 CLI 时在那一组上面用分组标题写 CLI 名，要改别的 CLI 的设置先在句子里换 CLI；整机共用的设置（如审批超时）单独成组，不放进某个 CLI 的分组里

## 2. 颜色

颜色只表达状态和可操作性，不做装饰。每种颜色只有一个意思：墨色是这屏最该做的事，蓝色是能点的文字，橙色是等你处理，绿色是在线，红色是危险；其余只有黑白灰。亮暗两套取值见界面稿开头的 `:root` 与 `[data-theme="dark"]`。

| Token | 用途 | 不要用于 |
|---|---|---|
| `paper` | 页面底（亮色白、暗色纯黑） | — |
| `gbg` | 纸上的灰底表面：卡片、分组列表、一件一行的等你列表、代码块、提示条；手机的弹层底。宽屏另有一套（下面「宽屏表面」） | — |
| `ink` | 正文、标题、主行 | — |
| `ink2` | 第二行、元信息、说明、状态词、时间 | — |
| `ink3` | 箭头、占位文字、空闲的空心圈、复制图标等图形 | 任何需要读的文字 |
| `faint` | 未连接的浅灰点、排队气泡的细边框、引用左边的竖条 | 文字 |
| `sep` | 细分隔线 | 粗于 1px 的边框 |
| `fill` / `fill2` | 输入字段、「＋」圆钮、行内代码、新任务里的胶囊 / 次按钮、分段控件的槽、进度槽、标签选中项的底 | — |
| `btn` / `btn-fg` | 墨色实心主按钮（亮色近黑、暗色近白）和它上面的字 | 一屏第二个按钮 |
| `bubble` | 你的消息气泡 | 其他任何底色 |
| `blue` | 能点的文字和链接、选中项的勾、未读结果的点 | 按钮底色、纯装饰、标签 |
| `orange` / `orange-ink` | 等你处理：橙点、大标题里的件数、角标、等你处理的件数 / 橙色的文字（类型词、原因、提示条文字） | 按钮底色、大面积底色、不需要你动手的状态 |
| `orange-soft` | 橙色提示条的底：安全提醒、定时任务停下的提示 | 普通提示 |
| `green` | 在线、开关打开、diff 的增行 | 按钮、「空闲」「成功」这类状态词 |
| `yellow` | 电脑状态里内存压力刻度的中段（绿到黄到红渐变的黄）；亮色 `#ffcc00`、深色 `#ffd60a`，三端同值 | 文字、状态点、任何别的地方 |
| `red` | 危险与完全放行：会丢数据或不可撤回的操作、失败原因、完全放行、diff 的删行 | 普通提示、「拒绝」 |
| `tc` / `tc-line` | 深色卡的底 / 暗色下深色卡的细边 | — |
| `term` | 终端视图的底 | — |
| `glass` / `glass-line` / `glass-shadow` | 玻璃：半透明底 / 细边 / 阴影（第 4 节「材质」） | 整屏、整栏 |
| `float` | 浮起的东西的阴影：深色停靠卡、对话框、墨色新建按钮 | 卡片、列表 |

- **要读的文字只用 `ink` 和 `ink2` 两档**，对比度都不低于 4.5:1；`ink3` 和 `faint` 只给图形。彩色文字只有蓝（能点）、橙（等你）、红（危险）三种
- **状态词不上色**：「运行中」「空闲」「已结束」「未连接」一律 `ink2`，含义由行首的图形表达（见下）
- 同一种含义在所有画面用同一个颜色：「中断」「结束会话…」「移除」这类危险操作在文字操作和菜单里一律红字，「重试」「撤销」一律蓝字。「拒绝」不会丢东西，不算危险，用次按钮
- **橙色只表示等你处理**：要你动手的才用橙。上下文占用超过 80%（要你压缩）、额度剩 20% 及以下（要你留意换用）、发送结果不确定（要你核实或重试）都算；连接检测里的「较慢」不要你做什么，用浅灰点加文字
- **红色实心按钮只用在确认对话框**里的删除、移除、退出、结束、切到完全放行；页面上的「拒绝」是次按钮
- 对话框标题一律用 `ink`，危险由按钮表达，不把标题染红
- 提示条统一用 `gbg` 底，只用文字颜色区分错误（`red`）；要你处理的提示（安全提醒、定时任务停下）用 `orange-soft` 底、`orange-ink` 字，见第 6 节「提示条」
- 项目头像是 `fill2` 底的圆，写项目名的首字，`ink` 字，不按项目上色：颜色只表达状态；同名项目由副标题里的路径区分
- **深色只给终端、图片查看器和深色卡**。深色卡是等你处理的事（第 6 节「终端卡」），两种主题下都是深色，卡里的命令块两种主题下都是纯黑。终端之外的代码块、命令预览不用深色底，用比所在表面高一级的表面：在 `paper` 上用 `gbg`，在 `gbg` 上用 `paper`；宽屏上是级 2 的卡

**宽屏表面**（网页 ≥900 宽）：宽屏不拿纯黑做内容底。宽屏的根 `.desk` 把上表的 `paper`、`gbg`、`lift`、`dialog`、`bubble`、`knob`、`float` 换成四级表面，其余规则照旧引用这些名字，所以只改这一处；手机不变（暗色手机仍是纯黑底）。相邻两级亮度差小但看得出：

| 级 | Token | 用于 | 暗色 | 亮色 |
|---|---|---|---|---|
| 0 窗口 | `s0` | 窗口底、侧栏 | #111113 | #ececef |
| 1 内容 | `s1` | 主区域：对话、设置、新任务所在的那张面 | #19191c | #ffffff |
| 2 卡 | `s2` | 卡片、分组列表、输入框、代码块、气泡；弹层里的分组列表 | #222226 | #f4f4f6 |
| 3 浮 | `s3` | 弹出菜单、对话框、侧栏选中行、侧栏的「新任务」按钮、分段控件的选中块 | #2b2b30 | #ffffff |

- 级与级之间不靠粗边：主区域相对窗口是 0.5px 的 `hair`（暗 rgba(255,255,255,.07)，亮 rgba(0,0,0,.08)）加圆角 12；卡不描边；能写字的框另用 `in-bg`、1px 的 `in-edge` 和聚焦时的 `in-edge-hi`（第 6 节「宽屏」），其余输入字段聚焦时描 1px 的 `edge-hi`（暗 rgba(255,255,255,.32)，亮 rgba(0,0,0,.3)）
- 浮层只有一种 `elev`：0.5px 的 `rim` 细边（暗 rgba(255,255,255,.10)，亮 rgba(0,0,0,.08)）、顶部 1px 内高光（只在暗色，rgba(255,255,255,.06)）和一组投影（暗 0 12px 32px rgba(0,0,0,.5) 加 0 2px 6px rgba(0,0,0,.3)；亮 0 12px 32px rgba(0,0,0,.14) 加 0 1px 3px rgba(0,0,0,.08)）。宽屏的 `float` 就是它，所有菜单、对话框和停靠卡共用，不另有投影
- 深色卡在暗色宽屏上仍是画面里最重的一块：`#0c0c0e` 底、0.5px rgba(255,255,255,.12) 的边，命令区纯黑；亮色不变
- 悬停和按下是盖在原底色上的薄层：`hov` 5%（暗用白、亮用黑）、`press` 8%；分段控件的槽 `seg` 比所在表面更暗一点，选中块抬到级 3；分隔线 `sep` 在宽屏是 0.5px、暗 rgba(255,255,255,.08)、亮 rgba(0,0,0,.08)
- 不加渐变背景、插画、彩色图标、发光和噪点，也不用毛玻璃铺大面积：宽屏上手机里坐在玻璃上的东西（输入框、分段控件）直接用所在的那一级表面

**状态图形**：行首一格，只放一个图形，旁边总写状态词。

| 状态 | 图形 |
|---|---|
| 运行中 | 墨色转圈（`ink` 的半开圆环，匀速旋转；系统要求减少动态效果时不转） |
| 空闲 | 空心灰圈（`ink3` 描边） |
| 等你 | 橙点（`orange`） |
| 未连接 | 浅灰实心点（`faint`） |
| 未读结果 | 蓝点（`blue`） |
| 在线（电脑、连接检测） | 绿点（`green`） |
| 已结束 | 不放图形，由日期分组说明 |

## 3. 字号与字重

| 字号 | 用途 |
|---|---|
| 34 | 大标题：主页、定时页的那句话，设置等一级页面的标题 |
| 22 | 居中整页状态的标题（如「暂时无法登录中继」）、空状态的标题、上下文百分比等单个大数字 |
| 20 | 卡片标题：终端卡标题、电脑卡名字、更新弹层的版本号、整页问题；回复里的一二级标题 |
| 17 | 正文、列表主行、按钮、输入框、弹层和对话框标题、会话顶部的标题 |
| 15 | 列表第二行、主页分组标题（「进行中」）、文字操作、小按钮 |
| 13 | 元信息、时间、说明文字、提示条、工具调用行、分段控件、日期分组标题、代码块和表格 |
| 12 | 会话顶部标题下那行状态、角标数字 |
| 10 | 只用于底部标签文字 |

- **宽屏**（网页 ≥900 宽）只用 11 / 12 / 13 / 15 / 17 / 22 / 28：正文 15 / 1.55，次要 13 / 1.45，辅助 12 和 11；大标题 22 / 700（侧栏的那句话）和 28 / 700（设置等页面标题）；卡片标题 17 / 600，弹层和顶栏标题 15 / 600；回复里的标题 17、15、13（一二级、三级、四级）。数字一律等宽数字（时间、百分比、计数）；标题字距 -0.02em，正文不调；`text-autospace: normal` 让浏览器在中文和西文、数字之间留空，不支持的浏览器照常显示，不往文字里插空格字符；等宽字 13 / 1.5，颜色比正文低一档
- 字重只用 400、500、600、700；700 只给大标题、卡片标题，以及头像字母和角标数字这类单字
- 代码、路径、命令用等宽：代码块、命令块和表格里 13 号，对话正文里的行内代码和路径 15 号，终端 12 号；行内代码是带圆角的浅底小块，不是整行高的底色
- 例外只有两处：配对码这类需要逐位核对的数字用更大的等宽字；宽屏有自己的一组字号（下面第一条）

**字体与平台字重**。设计稿按 Apple 设备的效果画：西文 SF Pro，中文苹方。苹方最粗只有 Semibold，所以 CSS 的 600 和 700 在中文上都显示为 Semibold。其他平台的中文来自 Noto Sans CJK 等字体，同一标称字重下明显更重（2026-09-30 在 API 36 模拟器上和设计稿同倍率对比过），因此：

| 设计稿字重 | Apple 设备 | Android 与其他平台的中文 | 其他平台的西文 |
|---|---|---|---|
| 400 | 400 | 400 | Inter Regular |
| 500 | 500 | 450 | Inter Medium |
| 600 | 600 | 500 | Inter SemiBold |
| 700 | 700 | 600 | Inter Bold |

- Apple 设备只调用系统自带的 SF Pro、苹方和 SF Mono，不打包也不引用它们的文件
- 其他平台的西文和数字用 Inter，代码、路径和命令用 JetBrains Mono；中文仍由系统字体回退。实现方式是把各个 Inter 字重登记在下调后的字重上，西文保持标称字重，只有中文随请求降一档：网页见 `web/src/styles.css`，Android 见 `Theme.kt` 的 `platformWeight`

打包的字体只用允许再分发的开源许可，并随附许可证原文：

| 字体 | 用途 | 来源 | 许可 | 许可证位置 |
|---|---|---|---|---|
| Inter 4.1（西文子集） | 其他平台的界面西文和数字 | github.com/rsms/inter | SIL OFL 1.1 | Android `res/raw/ofl_inter.txt`（设置 › 开源许可）；网页 `/fonts/OFL-Inter.txt` |
| JetBrains Mono 2.304 | 代码、路径和命令；Android 终端 | github.com/JetBrains/JetBrainsMono | SIL OFL 1.1 | Android `res/raw/ofl_jetbrains_mono.txt`；网页 `/fonts/OFL-JetBrainsMono.txt` |
| Sarasa Fixed SC 1.0.42（符号子集，裁剪方式见 Android `assets/fonts/README.txt`） | Android 终端里 JetBrains Mono 没有的符号 | github.com/be5invis/Sarasa-Gothic | SIL OFL 1.1 | Android `res/raw/ofl_sarasa_gothic.txt` |

## 4. 间距、圆角、阴影与材质

- 手机上列表和大标题左右留 24，卡片和分组列表离屏幕边 16，对话正文 20，停靠区和输入框 12；宽屏正文最宽 760
- 间距取 4 的倍数：4 / 8 / 12 / 16 / 20 / 24；宽屏只用 4 / 8 / 12 / 16 / 24 / 32 / 48
- 可点区域不小于 44×44，图标本身可以更小，由外层补足

| 圆角 | 用于 |
|---|---|
| 6 | 行内代码、图片角标 |
| 12–16 | 代码块（14）、深色卡里的选项（14）、命令块和深色卡里的输入框（16） |
| 18 | 提示条、输入字段、正在跑的命令那一条 |
| 20–24 | 分组圆角列表（20）、一件一行的等你列表（24） |
| 28–30 | 卡片：定时结果卡、电脑卡（28）；终端卡、对话框（30） |
| 38 | 底部弹层的上两角 |
| 胶囊（高度的一半） | 按钮、输入框、玻璃圆钮和胶囊、分段控件、标签、消息气泡 |

上表是手机的。**宽屏**收一档，不再有 28–30 的大圆角：行与菜单项 8–10（侧栏的行和筛选框 10，菜单项 8）；卡、输入框、代码块、气泡、分组列表、深色卡、终端面板 14；弹出菜单 14；对话框 18；主区域 12；按钮、胶囊和分段控件仍是全圆角。同一层级的东西圆角相同；嵌套时内层 = 外层 − 内边距，不小于 6（深色卡里的命令块、选项和输入框是 6）

- **阴影只给浮起的东西**：玻璃按钮和胶囊（`glass-shadow`），深色停靠卡、弹出菜单、对话框、墨色新建按钮（`float`；宽屏是 `elev`，见第 2 节「宽屏表面」）；底部弹层靠遮罩和圆角区分，不另加阴影。卡片和列表不用阴影，靠 `gbg` 和 `paper` 两种底色区分
- 不用彩色描边强调卡片。选中项在列表里是行末的蓝色 `✓`，在分段控件里是浅色小滑块（亮色 `paper`、暗色中灰），不用墨色；宽屏侧栏的选中行是一张级 3 的小卡（圆角 10）

**材质**

- **没有导航栏和标签栏**：内容铺满整屏，上下边缘用页面底色由实到虚的渐变淡出，内容从下面滑过。不做整屏模糊：整屏模糊既费电，又让下面的字糊成一片
- **按钮是浮在内容上的小块玻璃**：`glass` 半透明底、背景模糊（约 22，饱和度提高）、0.5 的 `glass-line` 细边和 `glass-shadow`。用在返回、⋯、齿轮这些圆钮（44×44），范围胶囊，底部的标签胶囊，会话顶部的分段控件和提示条，会话输入框，终端按键栏。模糊只用在这些小块上
- 终端视图上的玻璃是深色玻璃，两种主题一样
- 系统要求降低透明度时（iOS「降低透明度」、网页 `prefers-reduced-transparency`），以及平台画不了背景模糊时，玻璃换成不透明底色（所在页面高一级的表面，如 `paper` 上用 `gbg`），保留细边和阴影；上下边缘的渐变不变

### 动效

画面上的东西不凭空出现，也不凭空消失：因为你的操作或对方的消息而多出、少掉、变大变小的东西，用一小段过渡交代它从哪来、到哪去。动效只做这一件事，不做装饰。

**三档时长，一条曲线**

| 名字 | 时长 | 用在 |
|---|---|---|
| 快 | 120ms | 按下反馈、颜色和图标的切换（发送按钮从不可用到可用、↑ 换成 ■） |
| 常 | 200ms | 一个元素出现或消失、高度变化（气泡、状态小字、停靠卡、输入框增高、「回到最新消息」） |
| 慢 | 280ms | 整块界面进出（底部弹层、新任务从底部弹起、页面进出） |

- 进入和变化用减速曲线 `cubic-bezier(.2, .8, .2, 1)`（Android `tween` 配同一条曲线或无回弹的 `spring`，iOS 用 `.snappy` / `.easeOut`）；退出用同一档时长的 0.8 倍、`ease-in`，走得比来得快
- 不回弹、不过冲、不旋转；位移不超过 12px，缩放不低于 0.96。大的位移只给从屏幕边缘进来的整块界面（弹层、页面）
- 触感只在原生端：发出消息、点下允许 / 拒绝各一次轻触感，其余不震

**发一条消息**

- 按下发送：按钮缩到 0.96 再回来（快）；输入框清空后高度回落（常）；新气泡在列表底部上移 8px 并淡入（常），列表同时贴底，不出现先跳到底再冒出气泡
- 气泡下面的状态小字（「发送中…」「已送达电脑」「可能没发出去」）之间换字用淡入淡出（快）；小字消失时高度收拢（常），气泡不跳
- 输入框多行增高、附件托盘出现和移除：高度过渡（常）
- 发送按钮不可用 ↔ 可用、↑ ↔ ■：颜色和图标交叉淡入（快）

**对方在回复**

- 流式文字本身不做动效，字来了就显示；列表贴底时跟着内容走，你往上翻了就不拉回
- 工具行、「本轮用时」分隔线逐条淡入（快），不位移
- 「回到最新消息」胶囊：上移 8px 并淡入，消失时淡出（常）

**停靠卡（审批、提问、计划）**

- 出现：卡从输入框上沿上移 12px 并淡入，聊天区的高度同步让出（常），贴底的列表保持贴底
- 处理完消失：淡出并收拢高度（常的退出档），输入框平滑落回，不跳
- 展开 / 收起：高度过渡（常），内容淡入淡出

**界面进出**

- 底部弹层：从底边升起，遮罩淡入（慢）；关闭时落回、遮罩淡出
- 分段控件（聊天 / 终端、主题）：选中底块滑到新位置（常）
- 主页行的状态图形换形（转圈 → 橙点 → 空心圈）：交叉淡入（快）；行的增减和重排用位置过渡（常）

**网页的实现**：三档时长、退出时长、曲线、位移和缩放量是 `web/src/styles.css` 顶部的 `--m-*`、`--ease-*` 变量，减少动态效果时由同一处改写，其余样式只引用它们（`motion.test.tsx` 核对）。进入多半是插入时播一次的 CSS 动画；离开、高度变化和选中滑块由 `web/src/motion.tsx` 用 Web Animations 做：离开的元素在原位留一份点不到的副本播退出动效，所以停靠区、弹层、「回到最新消息」等不用推迟卸载；停靠区、输入框、附件托盘的高度从屏幕上现有的高度出发，可在中途被打断。只有新出现的元素播进入：打开长会话、向上加载更早的记录、列表重绘都不播（`useFresh`）。

**列表贴底和排队气泡**：贴底是瞬时的，不用平滑滚动：内容变高（队列行进来、运行中的工具变成一行、图片加载、停靠区或输入框让位）时，在同一帧把底部留在视野里，用户滚上去之后不再贴底。刷新或进入会话时，列表不先露出再挪动：虚拟列表在把估高修正完、历史补齐并落到底部之前不显示（占位用骨架），之后补进来的内容不让可见的内容移位。发出的消息从「发送中」「排队」到记录里的正式消息始终是同一个气泡：只有消息在运行中被排队、或排队超过约 1 秒才显示排队样式（行高用常档过渡，边框和底色用快档淡入淡出），变成正式消息时落定、不换位置；撤回时收拢加淡出。Alert 的进出用常档，淡入淡出加 0.96 倍缩放。

**网页打开会话**：先画真实顶栏、聊天区和可输入的草稿框，已知标题和状态直接沿用；按 ID 读取的会话也用同一页面，读取完成不重建输入框。正文优先展示本机已验证的密文缓存；没有可展示内容或虚拟列表尚在定位时，等待约 300ms 才出现消息形状的占位，放在滚动区外，不参与行高测量。超过 5 秒或读取失败，用页内状态和重试替代占位，保留草稿；断线仍由连接条说明。启动壳的等待文字也延迟 300ms，加载失败立即显示错误和重新加载；缓存与页面代码同时读取，页面代码到齐后直接画首页，不再额外等待一次懒加载占位。

**不做动效的地方**：键盘弹出（见新任务一节）、终端内容、流式文字、滚动本身、暗色亮色切换。

**减少动态效果**（网页 `prefers-reduced-motion`，系统「减少动态效果」/「移除动画」）：所有位移、缩放和高度过渡去掉，只留不超过 120ms 的淡入淡出；转圈改为静止图形。

| 文字操作 | `blue` 字、无底，行尾对齐；整宽时居中，高 44；危险时 `red` 字 | 重试、撤销、查看、「看全文 ›」「去处理 ›」、「添加设备」；更新弹层里主按钮下面的「检查更新」 |

按钮文字 17 号、600，高 48（小按钮 15 号、高 38）；禁用时整体 40% 不透明度，不换颜色。发送按钮是墨色圆钮，没有内容时是 `fill2` 底、`ink3` 箭头，表示还不能发。

**大标题**：主页和定时页的标题是一句话，说现在的情况，34 号 700，下面一行 17 号 `ink2` 的副标题。

- 主页按顺序取第一条成立的：断线时写连接状态，措辞和三种断线情况一致（「本机网络不通」「正在重连…」，这次打开后还没连上过写「连接中…」，「连不上服务器」）；有等你的事写「N 件事等你」，N 用 `orange`；否则「N 个会话在运行」；否则「没有等你的事」；一个会话也没有写「还没有会话」；范围是某个项目而它还没有会话时写「这个项目还没有会话」。副标题把运行中和空闲分开数（「1 个会话在运行，2 个空闲」「另有 2 个空闲」）；断线时副标题写「下面是上次的内容」，连不上服务器时写「正在重试」，右边蓝字「详情」；没有缓存可看时副标题换成原因，连不上服务器的原因用红字
- 定时页：「N 个任务停下了」（N 用 `orange`）／「N 个新结果」／「没有新结果」，没有任务写「还没有定时任务」；副标题数另一类（「另有 2 个新结果」）
- 设置等一级页面的大标题就是页面名（「设置」），没有副标题
- 大标题下面可以有一条提示条（有新版本、恢复申请待处理等），断线时它仍在大标题下面
- 空状态不在页面中间放墨色按钮：大标题下面一句话指向右下角写着字的新建按钮（「点右下角的「新任务」开始第一个会话。」「……也可以点右下角的「新定时」自己建。」），这屏唯一的墨色按钮仍是它。例外是还没有电脑：主操作是「添加设备」，这时右下角的新建按钮置灰；非管理端没有这个按钮，只写指向管理端的固定句（第 8 节）

**范围胶囊**：主页左上角（宽屏在侧栏顶部）的玻璃胶囊，高 44：项目头像加项目名，或「全」字头像加「全部项目」，末尾是向下的 `›`；名字放不下就省略。点开是范围菜单（手机是底部弹层，宽屏是贴着胶囊的弹出菜单），当前范围行末打蓝色 `✓`。一个会话和项目都没有时不显示胶囊。右上角对称的位置是齿轮圆钮，进设置。

**等你的事**：主页上排在最上面，不受范围限制（范围是某个项目时，别的项目里的事摘要前写项目名）。排序：审批、提问、计划、弹窗，同类先处理等得最久的。

- 最急的一件审批展开成终端卡（见下）；最急的不是审批时（只有提问、计划、终端弹窗、图片确认这类）不出终端卡
- 其余一件一行，放在一张 `gbg` 圆角列表里：橙点、标题（17 / 600）、第二行「类型 · 摘要」（15 号 `ink2`，类型词 `orange-ink` 600），行末 `›`，点进会话在停靠区处理。最多三行，再多写蓝字「还有 N 件」，点开是完整的等你列表
- 断线时这些事仍排在最上面，数量不变，但处理不了：终端卡和行里的按钮置灰，状态写「未连接」

**终端卡**：等你批准的命令画成一张深色卡（`tc` 底，两种主题都是深色），主页、会话停靠区和宽屏是同一张。先给要执行的内容，再给说明，自上而下：

1. 头部：橙点、类型词（13 / 600 橙色）、右边剩余时间（「剩 8 分钟，超时拒绝」；只有主页的卡写「，超时拒绝」，剩不到 1 分钟时橙色）
2. 标题（20 / 700）和「项目 · 机器」（13 号），机器只在账户里不止一台时才写；会话里不重复标题
3. 命令块：纯黑底、圆角 16、等宽 13 号，第一行前是橙色的 `❯`；命令可以在任意位置换行，不撑出卡
4. 说明：最多 2 行，放不下省略
5. 按钮行

规则：

- **命令没显示全时没有「允许」**：主页上命令最多显示 5 行，按整行截断，不切在半行，也不在卡里嵌套滚动。没显示全时按钮是「拒绝」和「看完整命令」，命令块下面一行写「还有 N 行没显示」（N 按屏幕上折出来的行数算）；点「看完整命令」就地展开全文，这时才出现「拒绝」「允许」，块下面写「共 N 行」和「收起」。不让人在没看全的情况下批准
- **拒绝时就地输入**：点「拒绝」后卡里就地出现输入框（占位「说说该怎么做，可以不填」），按钮变成「取消」「拒绝」；写一句说明或留空再确认
- **提交后缩成一行**：提交后整张卡锁住、缩成一行状态（「已允许」「已拒绝」），下一件事顶上来；没送到时这一行写原因和「重试」，「重试」重发同一个选择
- 点卡片标题进这个会话
- 永久授权在原生终端处理，客户端只允许单次审批，支持边界见 [architecture §7](architecture.md#7-审批)
- 宽屏（网页 ≥900 宽，Android、iOS 的平板宽度）上整页里的审批和计划，按钮行不撑满，整张卡最宽 480，靠左对齐内容；会话里的停靠卡不受这条限制（见「宽屏」的会话一条）

**底部**：手机的会话页和定时页底部浮着两样东西，左边是两个标签（会话、定时）的玻璃胶囊，标签是图标加 10 号字，选中的标签是 `fill2` 底；右边是写着字的墨色按钮：会话页「新任务」（`square-pen`），定时页「新定时」（`plus`）。设置不是标签，从主页右上的齿轮进入；设置及其下级页面左上是返回，没有底部这一组。

- 会话标签的角标是等你处理的件数：橙底数字（亮色 `orange-ink` 底白字，暗色 `orange` 底深色字，保证对比度），超过 99 写 99+
- 定时标签的角标见下面「定时列表」
- 断线时右下角的新建按钮置灰；还没有电脑时同样置灰

**设备行**（设置页）：客户端以行首图标开头（浏览器 `globe`，手机 `smartphone`，平板 `tablet`），然后是名字；状态（「当前」「已配对」「刚刚使用」）总在行尾右侧，不挪到名字旁边。电脑在设置页是卡片，见下面「电脑卡与额度」；在设备页是普通的设备行（`laptop`），行尾写「● 在线」或上次在线时间。

**电脑卡与额度**：设置页的电脑分组里每台电脑一张 `gbg` 卡（圆角 28）：名字（20 / 700），下面一行状态点和「在线 · 0.58.0」这样的状态与版本；不在线的电脑只写上次在线时间（「2 小时前在线」），卡改成只有细边、没有底色，不显示额度。在线的电脑下面每个装了的 CLI 一行额度，点额度行进账户额度页。「添加设备」是电脑卡后面的一行蓝字按钮（`plus`），非管理端在同一位置写指向管理端的固定句（第 8 节）。

- **额度一律写「剩 N%」**，后面是重置时间（「4 小时 29 分后重置」），下面一根细进度条，画的是剩下的部分（`ink`，槽是 `fill2`）。一行只写剩得最少的那个窗口；电脑页和额度页按窗口逐个列出，同样写「剩 N%」
- 剩 20% 及以下（即已用到 80%）时数字（`orange-ink` 600）和细条（`orange`）变橙；用完写「已用尽」。不会因此自动切换 CLI、模型或拦住发送
- 离线或过期时保留上次记录，细条变灰；读不到数字的情况（「暂未获取额度」「未获取」「等待更新」）不画成剩 0% 或剩 100%，规则见 [architecture · 账户额度](architecture.md#账户额度)
- 上下文占用不是额度，仍写「已用 N%」，在会话设置和 ⋯ 菜单里

**列表行**（设置类的分组圆角列表）：主行 17 号，第二行 13 号 `ink2`，行高不小于 50；行间 `sep` 细线，从文字起点开始画。值写在行尾，`ink2`。导航行末尾放 `›`，操作行（如「清理查看缓存」「重新读取」）用蓝字、不放 `›`，危险操作用红字。

**会话行**：行首一格放状态图形（第 2 节），进行中和需要处理的会话，第一行标题（17 / 600，右边 13 号时间），第二行「状态 · 预览」（15 号 `ink2`，最多两行），第三行（13 号 `ink2`）只写范围内不止一种的项目、CLI、机器，依次用「 · 」隔开，分叉出的会话在最前面写「分叉」；都没有就只有两行。断线时没结束的会话都是浅灰点加「未连接」，不沿用断线前的「运行中」。已结束的会话只占一行：标题（400），右边时间（全部项目里是「项目 · 时间」），不带状态图形，由日期分组标题说明它们已经结束。时间在今天和昨天的分组里写时刻，近 7 天写星期，更早写日期。

**定时列表**：结果只指已请求通知的运行；一个任务只表达「有新结果」，不显示未读数字。页面自上而下：

- **停下的任务**：每个一张 `gbg` 卡（圆角 28），排最前，按停下时间倒序。卡头是橙点、标题（600）和时间；摘要最多 2 行、15 号 `ink2`，以 `orange-ink` 600 的「已停下 / 没能运行」加原因开头；右下蓝字「去处理 ›」，点卡片或它进详情恢复
- **新结果**：每个有新结果的任务一张卡（包括仍有新结果的已结束任务），按最新结果时间倒序。卡头是蓝点、标题（600）和时间，摘要最多 4 行、17 号 `ink`，卡底一行是频率（13 号 `ink2`）和蓝字「看全文 ›」。有新结果卡时，分组标题右侧蓝字「全部标为已读」读完这一组
- **其他任务**：没有新结果的未结束任务，一个任务一行，不带行首图形：标题（17 / 500，已暂停为 `ink2`）、时间，摘要最多两行、15 号 `ink2`，第三行 13 号 `ink2`。按最新结果时间倒序，从无结果的按下次时间排在后面
- **已结束**且无新结果的默认收起，点开在原地展开

第三行（卡里是卡底那行）依次为墨色转圈「正在运行」、任务时区的频率、范围内不止一种的项目 / CLI / 电脑、目标对话、已暂停、未连接；非本机时区用「（北京时间）」等城市名，不写 IANA 原文，列表不写下次时间（从未运行时摘要除外）。首次正在运行且没有结果时，摘要只写 `ink2` 的「还没有结果」，运行状态只放第三行；已有结果时继续显示最新结果摘要。点提供读屏标签：停下的「需要你处理」，新结果「有新结果」。

定时行时间专用：今天 `HH:mm`，昨天「昨天」，7 天内星期（跨年也一样），更早 `M月D日`，更早且跨年 `YYYY年M月D日`，不写相对分钟；会话行规则不变。结果时间统一取结束时刻，缺失时取开始时刻，再缺失取计划时刻；需要处理的卡取最新运行的该时刻，没有运行则取任务更新时间。

定时标签和宽屏侧栏：有需要处理的任务时是橙底数字（和会话标签同一画法），只数可见且未结束的待处理任务，超过 99 写 99+，读屏「N 件需要处理」；否则有新结果时只放 9px `blue` 点，读屏「有新结果」。App 图标只计待处理数字。手机左滑只露一个 `blue` 底白字操作：新结果卡是「已读」（check），其他有结果的行是「未读」，滑到底执行；需要处理且无新结果或从无结果的不滑。网页手机可用行内读屏 / 键盘辅助操作，宽屏另有右键菜单。

详情依次为顶部（标题，下面一行频率与下次时间，已停下或发到对话时用对应的说法）、需要处理的提示与墨色「恢复」、运行中卡、最新结果卡、更早记录、最多三行的任务描述与编辑、设置（什么时候、完成后通知、在哪运行 / 发到、权限、任务名等）、创建信息。结果卡是 `gbg` 卡，头部 13 号 `ink2` 时间，进入时未读用蓝点，右侧蓝字「对话 ›」；只有 agent 或 agent_and_daemon 来源的通知文字，且去掉首尾空白后与最终摘要不同，才作为 17 / 600 标题；其余不显示标题，列表摘要规则不变。正文用对话 Markdown 的最终回复全文，读取未完成或失败时用最终摘要或原因。手机按整段、整表格、整列表折叠到约八行，蓝字「展开全文 ⌄」，不切半行、不渐隐；宽屏不折叠。没有更早的运行时不显示「更早」分组。更早记录的蓝点放行首固定一格，时间 13 号 `ink2`、摘要 15 号两行；无通知的运行按天折叠。立即运行一次、标为未读、暂停 / 恢复、删除任务…放在 ⋯ 底部弹层（画法见「弹层与对话框」），顶部写任务名和「项目 · CLI · 谁创建 · 日期」，删除需确认。

需要处理的提示条用 `orange-soft` 底、`orange-ink` 文字、行首 `info`；提示条、紧随其后的墨色按钮和结果卡左右对齐，共用同一内容列，网页宽屏也受 760 的最大宽度约束。

拿到在线完整列表并建立快照后，打开详情只读该任务全部结果，保留本次停留进入时的蓝点。只有缓存或首次在线读取失败时仍展示最新结果与全文，并从「更早」排除它，但不标已读，也不显示进入时蓝点。停留中新结果也算已读，但最新结果卡保持原内容，点蓝字「有新结果」才换；这只在进入时已有一个结果在显示时适用，进入时没有结果就没有可保持的，运行出第一个结果后直接显示它，不出现「有新结果」，「还没有运行」也随之消失；页面后台期间不标已读，回到前台补蓝点。标为未读在执行时重新取最新任务，只移除最新结果的已读记录，并返回列表或取消宽屏选中。刚标为未读的结果暂不参与当前页面的自动标读，包含返回来源对话时的首次页面交接；离开当前页面或转入后台后解除保护，下次查看恢复正常规则。已读仍保存在本设备，首次加载已有结果视为已读，按完整列表裁剪；已读时精确关闭对应系统通知。宽屏初次打开不自动选中，右侧居中 15 号 `ink2`「选一个任务查看结果」，下面一个次级按钮「新定时」，新建也可以从侧栏顶部的「新定时」进入。

**项目行**：项目头像、名字（17 / 600），第二行 13 号 `ink2` 写路径和会话数，和主页的等你、进行中同一口径（「~/Code/foo · 1 个待处理 · 3 个进行中」），为 0 的部分不写，都为 0 时它的电脑都不在线就写「电脑不在线」，否则只写路径；范围菜单里「全部项目」一行同样计数，都为 0 时写项目个数；行间 `sep` 细线，行高不小于 52。列表先「常用」后「其他」，只有一组时不写分组标题；超过 8 个时顶部有搜索；最后一行是蓝字的「＋ 新项目…」，`＋` 占头像的位置。行尾按所在的地方放一样东西：范围菜单是当前范围的 `✓`，选项目是 `›`，项目管理是 `⋯`（常用和移除）。移除要确认，对话框里是红色实心的「移除」，没有撤销。

**筛选框**：胶囊形、`fill` 底、高 40，左边 `⌕`，占位文字「按标题筛选」（`ink3`）；有内容时右边是 `✕`。宽屏占位右边写快捷键。

**分组标题**：主页的「进行中」15 号 600 `ink`；已结束的日期分组比它轻一级，13 号 400 `ink2`；设置类页面圆角列表上方的组名 13 号 `ink2`。右侧可以放计数（400）或一个文字操作（15 号蓝字 + `›`）；也允许不带 `›` 的蓝色文字操作，如「全部标为已读」，点击区域至少 44×44。

**提示条**：两种位置，同一套颜色。

- 页面里的提示条（banner）：`gbg` 底、圆角 18、13 号 `ink2`，左边说明、右边最多一个文字操作，放在大标题下面或所在分组下面。用于推送未开、保存失败、电脑未连接（「iMac 未连接，显示的是上次的状态」）、罕见的页面状态。错误用 `red` 字；要你处理的（恢复申请、定时任务停下）用 `orange-soft` 底、`orange-ink` 字
- 会话里的提示条（strip）：会话顶部分段控件下面的一条玻璃胶囊，13 号 `ink2`，左边图标、中间一句、右边最多一个文字操作。用于断线、终端尺寸变化、定时（「定时 · 每小时，下次 今天 15:00」和「管理」）。安全提醒是同一位置的橙色提示条（`orange-soft` 底、`orange-ink` 字）

**连接状态**：只在没连着服务器时出现。按离本机最近的一段故障写一句，各带一个图标：`wifi-off`「本机网络不通 · 显示的是上次的内容」、`loader-circle`「正在重连…」、`cloud-off`「连不上服务器 · 正在重试」，最后一种右边有「详情」。主页和宽屏侧栏由大标题说（见「大标题」，宽屏侧栏底部也写连接状态，点开是连接检测），会话里由分段控件下面的提示条说。没有缓存可看时，连不上服务器用 `red` 并直接写原因。说过的事不在别处再说一遍：这时没结束的会话都是浅灰点加「未连接」，不出「××× 不在线」状态卡，读取失败也不出红条；等你处理的事和会话标签上的数字不因断线消失，等你的事仍排在最上面，按钮置灰。哪种情况算哪一段见 [architecture · 断线时显示什么](architecture.md#断线时显示什么)，画面见 [client-v60 · 断线](design/client-v60.html#link)。连接检测里延时正常是绿点；服务器 500 ms 以上、电脑 1500 ms 以上写「较慢」，用浅灰点，不用橙色（橙色只表示等你处理，见第 2 节）。

**会话顶部与视图切换**：会话页顶部左边是返回（玻璃圆钮），中间是标题（17 / 600，一行，放不下省略）和下面一行状态（12 号 `ink2`），右边是 ⋯（玻璃圆钮；上下文占用高时加橙点）。

- 状态行写状态和审批模式，如「运行中 · 询问」「空闲 · 自动」「计划待批准 · 计划」；只有完全放行用红字，其余 `ink2`；读不到审批模式时（包括启动中）只写状态，不写「CLI 配置（未读到）」这类话；已结束的会话只写状态。CLI、项目、机器和目录放在 ⋯ 菜单顶部，不占顶部，会话 ID 不显示
- 标题下面居中一个玻璃的分段控件「聊天 / 终端」，选中项是浅色小滑块，不用墨色。宽屏上分段控件在工具栏右侧、⋯ 的左边，多一项「并排」，顶部只有一行
- 选了哪个视图记在这台设备上，之后打开任何会话都是它；显示不了时（窗口放不下并排、会话已结束或电脑离线）临时显示聊天，不改记住的值；新建会话后自动进终端不算选择
- 分段控件只用于同一设置的多个取值和这类视图切换，如推理强度、外观的自动 / 亮色 / 暗色、按 CLI 分组的设置；底部的会话 / 定时是标签，不是分段控件（宽屏侧栏底部的会话 / 定时用分段控件）
- 选模型的列表（会话设置、项目设置、电脑的新会话默认模型）超过 5 个时只列前 3 个和已选的那个，其余收进末尾的「全部模型」，免得列表下面的推理强度被挤出屏幕
- 对话里你的消息是 `bubble` 浅灰气泡（17 号，靠右），回复不带底；别的客户端或电脑终端发的消息在气泡下写来源（第 8 节）
- 终端视图整屏深色（亮色主题下也是），底部是玻璃按键栏

**等待事项（停靠区）**：进会话时，审批、提问、计划、终端弹窗、图片确认等要你处理的事默认展开，停靠在输入框上方：来这个会话多半就是为了处理它。所有类型都用深色卡的壳（`tc` 底、圆角 30、`float` 阴影）：审批是终端卡；提问是题目加一组选项行（半透明白底、圆角 14，选中的是白底黑字），单选点一下就答，多选勾好后点「提交 N 项」；计划是正文（15 号）加「展开全文」；终端弹窗写弹窗标题和「去终端处理」；图片确认同样画在这张卡里。

- 展开后只有一行头部「● 类型　元信息　收起」，元信息是「还有 N 项 · 剩 X 分钟」这类，只写剩多少时间，不加「，超时拒绝」（这句留给主页的终端卡），计划的「展开全文 ›」放在「收起」前面；摘要只在收起时显示，不在内容里再写一遍标题
- 内容区最高约占会话内容区可视高度的 60%（至少 240，且给输入框和一点聊天留出位置），超出时内容区自己滚动，操作按钮固定在下面；命令和计划正文不单独限高，跟着内容区滚动
- 点「收起」后这一项收起成一行深色胶囊「● 类型 · 摘要 · 处理」，末尾是向下的箭头，按事项 ID 记住，换成新的一项又默认展开。输入框里有没发出的草稿（文字或图片）时新来的一项也只留这一行，免得把正在写的消息挤开；输入框只是有焦点不算，电脑上发完消息焦点一直留在输入框里。会话内容区太矮放不下时也只留这一行，点它进整页
- 只有状态点和类型词用橙色。多项时只停靠优先级最高的一项
- 处理后聊天里留一行「已允许 / 已拒绝」

**输入框**：底部浮着的玻璃胶囊，左边「＋」（`fill` 圆钮）、中间正文（17 号）、右边发送（墨色圆钮）；正文从一行起步，最多约六行。「＋」只做一件事：点一下直接打开相册选图片，不弹菜单；电脑声明能收文件时例外，「＋」在上方弹出「照片和视频 / 文件」两项，相册里图片和视频一起选，视频按文件发送，不用到「文件」里去找（[session-files.md](session-files.md#从相册选视频)）；iOS 上剪贴板里有图片时先问「相册」还是「粘贴」，因为系统的输入框不接受粘贴图片，没有别的入口。模式、模型、上下文不常驻，放在 ⋯ 菜单里，上下文占用高时在 ⋯ 上加橙点。输入框里不加提示行，胶囊始终一行起步：审批模式写在会话顶部标题下那行状态的后面，完全放行用红字，读不到（包括启动中 CLI 还没报出）时不写。占位文字里的快捷键按平台写：Mac（及其他 Apple 设备接键盘时）写「⌘↵」，其他写「Ctrl+Enter」，触屏设备（主指针不是精确指针）不写快捷键，如「消息 · ⌘↵ 发送」「描述任务，Ctrl+Enter 开始」。

从输入框操作行打开的小菜单或浮层（附件、发送选项、CLI、模型等）在打开、选择和关闭时都不改变输入框位置、输入焦点或键盘状态：键盘原来开着就保持，原来关着也不唤起；选择后进入系统选择器或整页弹层的动作遵循目标界面的键盘规则。

- 输入框右侧只有一个按钮：运行中且输入框空着时是墨色圆形 `■` 中断，打字后变回发送；运行中点发送是插入这一轮，长按选「这一轮结束后再发」，有草稿时中断走 ⋯ 菜单；输入框上方不放排队数量、中断或工具摘要这样的独立一行
- 排队的消息作为待发气泡留在对话末尾（细边框 `faint`、无底，文字 `ink2`，下面一行写等什么和「取消」），不另开队列页；新会话启动中的第一句话也是待发气泡，只出现这一次；正文最多 4 行，点开看全文，说明行只占一行，放不下时省略说明、保留操作。说明只用几种说法：「插入这一轮」「这一轮结束后发」「等 <CLI> 就绪后发出」（新会话的第一句），以及「已暂停」「正在取消…」「取消没成功，仍在排队」这类少数状态；不加「排队 ·」「已送达电脑 ·」前缀，也不加「等输入框就绪」这类过程；排着不止一条时后面加「 · 第 N 条」，别的客户端排的再加它的名字
- 发送失败的消息只分两类，原因写短，不加「不会自动重发」这类附加说明：确定没发出去的（会话已结束、CLI 没认出图片、电脑明确拒绝）红字「没发出去：<原因>」，配「重试」「放回输入框」中可用的；不确定发没发出去的（已送到终端但没确认、读不到终端输入框、连接超时）橙字「可能没发出去：<原因>」，连接中途断开时原因统一为「连接中途断了」，配原来的操作（去终端、重试、移除此提示）。后者要你去核实或重试，算等你处理，所以用橙色
- **草稿随对话保存**：文字和图片加密留在本机，刷新网页、重开应用或切换对话后恢复，保留图片顺序和原图开关；移除的图不再恢复，发出的内容交给待发消息持有，到 CLI 确认或用户明确移除后清掉，退出账户全部清掉。保存失败要说明内容还没保住，不能静默丢弃。
- **草稿图片**：主体点开消息图片用的同一个大图查看器，多张左右翻。每张读作「图片 N，共 M 张」并读出处理、上传、失败或已传到电脑的状态；独立删除按钮读作「移除图片 N」，✕ 外观仍在缩略图右上角，44×44 触区以该角为中心、仅左下 22×22 覆盖缩略图，每格在上方和右侧留足空间使触区不被滚动容器裁切且不压住相邻图片，缩略图尺寸不变、其余区域均可点开预览或重试。手机原图开关同样有 44 高的点击区，可见图形不变。原图提示三端统一为「原图保住画质；CLI 仍可能缩小过大的图片。」
- **每张图片的失败**：缩略图标「失败」，点开查看这张的中文原因和处理办法；格式、尺寸、大小这类永久拒绝只给「移除」，连接或电脑空间恢复后可继续的才给「重试」。不显示底层英文异常。托盘下只有一张失败时写它的原因；多张原因不同写「N 张图没加上，点图片看原因」，相同则只写这个原因。失败项保留，所有图片就绪前不发送。
- **失败消息的附件**：「可能没发出去」（包括需要到终端处理的图片）仍保留缩略图；本机还留着附件源文件时给「放回输入框」，把文字、图片和原图选项还原，重新核对上传后才能再发。没有本机副本时不显示这个动作，不能只恢复文字却让用户以为图片也回来了。
- **待发与正式消息图片**：网页共用比例、96px 高度、最多四张和「+N」折叠规则，CLI 确认前后不重新排成另一种图阵；Android 和 iOS 的四图行按可用宽度一起等比缩小，末张和角标不能被屏幕右边裁掉。
- 会话已结束或电脑离线时，输入框的位置换成状态卡（`gbg` 卡）：先写原因，已结束的下面是墨色「恢复会话」

**新任务**：会话页右下的「新任务」从底部弹起一张整页弹层。手机上它和会话页是同一个骨架：顶栏说在哪，底部一个输入框写要做什么；宽屏的画法见「宽屏」一节（那里仍是一句话加输入框）。

- 顶栏：左上关闭。中间两行，都没有胶囊底色：第一行是项目（头像、17 / 600 的名字、小下箭头），点开选项目列表；账户里不止一台电脑时第二行是电脑名（12 号 `ink2`、小下箭头），点开是机器列表（每台写装了哪些 CLI，不在线的置灰），选定即关。项目和它所在的机器是一起的，所以写在同一处；只有一台电脑时没有第二行。电脑不在线时照写它的名字，提示条的「换电脑」打开同一个列表。右边留空：发送不在顶栏。范围是全部项目时，点「新任务」后先弹出项目列表，选中后再到这一页
- 键盘弹着时点项目或电脑：先收起键盘，等它收完再弹出选择层，两个动作不叠在一起；CLI 菜单和模型面板不动键盘
- 中间空着，只放提示条（电脑不在线、没有某个 CLI、启动失败）和「正在 … 上启动…」
- 底部是输入框，贴在键盘上方，和会话的输入框是同一种画法（`gbg` 底、圆角 22、细边）：上面是文字，占位「要做什么」和输入的字都是 17 号正文，多行时长高到上限后在框内滚动，选的图片和文件排在文字下面；下面一行从左到右是「＋」（加图片或文件）、CLI（标、名字、小下箭头，只列目标机器装了的、当前的打蓝勾，默认是这个项目上次用的；只装了一个 CLI 时不出现）、模型（设置摘要，末尾小下箭头）、墨色圆形发送键（没写字时置灰）。CLI 和模型默认没有底色，14 号 `ink2`；弹起时键盘已弹出
- 摘要写「模型 · 推理强度」，如「GPT-6-Astra · high」；推理强度取当前选择，没有明确选择时取实际使用的默认值，没有选择项、只有一个固定值或尚未读到时不写这一段；机器不在摘要里。新任务没有审批模式，不写，也没有红色的「完全放行」：新会话的审批模式一律是这台电脑上这个 CLI 的默认（「设置 › 这台电脑」里的新项目默认设置，没设就是 CLI 自己的配置），不在新任务里选，之后在会话的 ⋯ 菜单里改。CLI 已在旁边选了时不写 CLI 名，只装一个 CLI、旁边没有 CLI 时摘要以 CLI 名开头。模型为「默认」时写默认模型的名字；上下文窗口不写进摘要。模型还没读到时写占位（「读取设置…」「默认模型」），胶囊不会是空的。按实际内容测量工具行：完整摘要放不下时，CLI 控件先收起名字，只保留标和小下箭头，读屏仍写「CLI：Claude Code」等完整名字；仍放不下才省略模型尾部，推理强度前至少保留约六个模型名字字符（如「Opus 5… · medium」），推理强度始终完整。模型面板开着时摘要控件保持选中底色，关闭后恢复；读屏标签为「模型：…，推理强度：…」
- CLI 点开是贴在该控件上方的弹出菜单，无遮罩、无标题，当前项末尾蓝色 `✓`，名字前有 CLI 的标；选择即关闭。模型点开是输入框上方的浮层面板，主页面依次是「模型 / 完成」标题、推理强度、Claude Code 的上下文窗口、默认模型和常用模型列表（始终包含当前模型）、有更多模型时的「全部模型 ›」。推理强度的小标题下面一行等宽分段放齐所有选项（最多六个），没有选项时隐藏，只有一个固定值时写 13 号 `ink2`「推理强度固定为 X」；上下文窗口一行分段「1M · 标准 200k」，只有标准窗口时保留一句说明。保留不可用原因。每次选择立即更新摘要，面板不关闭；换模型时保留新模型支持的当前推理强度，否则取新模型的默认值。「全部模型 ›」进入同一面板里的第二页，标题「‹ 全部模型」可返回，完整列表的当前项打蓝勾；选中后应用并回到主页面，不原地展开长列表。「完成」、点外部（包括输入框和键盘）、返回或再点模型控件都会保存选择并关闭；目标项目、机器或 CLI 改变时丢弃旧目标的未提交选择。两者都用宽屏浮层的级 3 表面、0.5px `rim` 细边、`float` / `elev` 阴影和圆角 14，触屏选项至少高 44。再点同一控件关闭，不重新打开
- 模型面板使用顶栏与输入框之间的可用空间，随内容长高、上限约 600（网页 px、Android dp、iOS pt，下同），标题始终固定。主页面只有在推理强度和 Claude Code 的上下文窗口下方还能完整露出约两行模型（按实际行高的两倍加少量留白，通常约 96）时，才把这些控件固定在顶部、让下方模型列表滚动；空间不足时，推理强度、上下文窗口、模型列表和「全部模型」入口作为一个整体滚动，初次打开从顶部开始，先看到推理强度。键盘开合或可用区域改变时重新判断，切换固定与整体滚动不重建内容或重置滚动位置，操作中不跳回顶部；空间变大导致原滚动位置超出范围时只收回到新的边界。「全部模型」第二页只有列表滚动，返回标题固定。打开即展示输入框已经读到的模型，后台刷新就地更新。只有首次尚无缓存时用占位并预留适中高度，键盘收起后不留下大片空白。只选模型，不放项目名和路径、审批、说明文字、「设为常用」和「移除项目…」。定时任务和项目管理里的设置仍用现有底部弹层
- CLI 菜单和模型面板遵循上面「输入框」的小菜单键盘规则；iOS 的 CLI 控件保留原生系统菜单，网页手机沿用全局可视区域布局
- 当前模型没有自动模式、而这台电脑的默认审批模式恰是自动时，新任务不能开始，提示条说清原因：只是这个模型没有，动作「换模型」打开同一个模型浮层；整个账户都不支持自动模式，动作「去改默认」进入这台电脑的设置页
- 换 CLI 时摘要随即换成那个 CLI 在这个项目里的一套设置，已写的字和图片保留。CLI 常驻而模型不常驻，是因为每个任务都可能换 CLI（[architecture §13](architecture.md#13-daemon-设置与远程新建会话)）
- 键盘弹出时画面不动：键盘只让内容区变矮，不增删内容，免得跟着键盘动画跳动
- 发出后会话接替这一页：会话启动成功就进入它，新任务不留在返回栈（网页是历史记录）里，在会话里按返回回到打开新任务之前的页面（主页）；发送失败则留在新任务，内容不丢。新项目的第一个任务同理
- 宽屏上新任务是右边主区域本身，不是弹层：同一句话、任务输入和摘要，摘要在输入下面一行；任务输入、附件和摘要那一行装在一个级 2 的圆角框里（聚焦时细边变亮），看得出往哪写；那句话里的项目在范围已选定时是普通文字

**终端按键栏**：终端下面的玻璃按键栏（Esc、方向键、Tab、Ctrl+C 和白底的「键盘」）是给触屏用的；网页宽屏上主指针是精确指针（`(pointer: fine)`，鼠标或触控板）时不显示，直接用键盘；触屏照旧显示。Android、iOS 不变。

**弹层与对话框**：

- 底部弹层：`gbg` 底、上两角圆角 38、顶部有抓手，标题 17 号 600；里面的内容是 `paper` 底的圆角列表（暗色下是高一级的灰）。只有需要确认提交时右上角才放「完成」或「取消」。点遮罩或抓手关闭
- ⋯ 菜单（会话、定时任务、项目管理）和选项目是同一种底部弹层：顶部一行粗体写它是关于什么的（会话是「CLI · 项目 · 机器」，机器只在账户里不止一台时才写，下一行写目录），下面是三组圆角列表。会话的三组依次是：设置项（审批模式、模型、上下文，写成「名称 …… 值 ›」，值在行尾 `ink2`，完全放行红字、上下文高时橙字）；操作（Android、iOS 先有一行「项目设置」，网页没有；然后是重命名、分叉会话、中断）；结束会话（红字「结束会话…」）。中断是红字行，其余操作是 `ink` 字的普通行；不用居中的按钮，也没有单独的「取消」卡片
- 已结束的会话只剩重命名和分叉会话（原生端保留项目设置），电脑离线时菜单里只有顶部的信息（原生端保留项目设置）。暂时做不了的一项不藏起来：文字按禁用显示，下面一行 13 号 `ink2` 写什么时候可以；点了以后要等结果的一项就地写进度，失败原因用红字写在它下面，菜单不关
- 宽屏上 ⋯ 菜单是贴着 ⋯ 弹出的菜单，内容和分组与手机的弹层相同；从一个控件上做的短选择（新任务句子里的 CLI）也是贴着那个控件弹出的菜单，不带标题和遮罩；其余弹层是窗口正中的对话框，没有拖动条
- 整页弹层（新任务、新定时、回答提问）从底部弹起，左上关闭，右上是提交（发送或「创建」）
- 更新弹层里，「检查更新」作为文字操作放在主按钮下方
- 对话框：居中，`gbg` 底、圆角 30、`float` 阴影；标题 17 号 600 `ink`，说明 15 号 `ink2`，按钮左「取消」（次按钮）右确认（墨色或危险按钮）；宽屏的取值见「宽屏」

**代码块**：等宽 13 号、圆角 14、表面规则见第 2 节。停靠区里的不单独限高，跟着内容区滚动；终端卡里的命令块见上面「终端卡」；回复里的见[第 7 节](#7-对话正文)。

**添加设备**：当前管理端（网页、Android 或 iOS Client）能添加和移除其他设备（协议 10，[architecture · 配对](architecture.md#配对)）。三端都在设置的电脑组和设备页放「添加设备」，在管理端的无电脑空状态保留说明与按钮。非管理端在同一位置指向当前管理端的名字，措辞见第 8 节；Machine 不显示管理或接任入口。移除设备保留电脑档案；从档案「重新加入并接续会话」，永久删除记录另行确认。

**工具调用**：一次调用一行，13 号 `ink2`，行首 `◌` / `✓` / `✕`（`ink3`），后面是等宽的命令，行尾写退出码或「后台运行」；两轮之间的分隔线上写「本轮用时 4 分 12 秒」，计时总说清是什么的时间；连续完成的折成「运行了 N 条命令」，点开只列命令。正在跑的命令在对话末尾单独一条（`gbg` 底、圆角 18）：墨色转圈、等宽命令（放不下省略）、「已运行 m:ss」。不显示输出，不做详情页，不放跳转终端的入口。

单条完成、分组展开后的每条、正在运行、后台运行和文件改动行都可以点一下原地展开，再点收起；收起仍是现有的一行，不加新箭头或图标，按下反馈与工具分组相同，无障碍读作按钮并说明展开状态。展开状态随行保存，滚动回收和重渲染不丢、不串行。展开显示客户端持有的最完整原文：命令优先从 input 的 command / CommandLine / cmd 取值，纯文本 input 原样显示，否则用未缩短的 title；文件改动用完整路径，不取预览里的相对路径或第一行。工具名是唯一可用内容时就原样显示。

展开的命令块沿用审批命令块的等宽 13 号、1.5 行高、任意处折行和圆角 16，文字保持工具行原色，保留换行和 heredoc；最多约 12 行，超过后块内纵向滚动。右上角复用回复代码块的复制按钮（「复制代码 / 已复制 / 复制失败」），复制完整原文，点击不收起；文字可以长按或拖选，选字不收起，网页存在选区时忽略该次点击。网页的命令和工具分组展开 / 收起立即改变高度，只给新内容 120ms 淡入；不做逐帧高度动画，避免虚拟列表反复测量和调整位置，系统减少动态效果时取消淡入。原生端沿用各自现有过渡。

**宽屏**（网页 ≥900 宽、平板）：按桌面的样子画，不是手机放大。窗口、侧栏和主区域是四级表面（第 2 节「宽屏表面」），尺寸、圆角和字号在 `.desk` 作用域里覆盖手机的取值，手机的版式不变。界面稿 client-v58 里的宽屏画面是更早的画法，宽屏以本节和实现为准。

- **窗口与主区域**：窗口是级 0，侧栏直接画在它上面，宽 288，内边距 8；主区域是一张级 1 的面，圆角 12，0.5px 细边。顶栏高 52：左边标题（15 / 600）和状态，右边分段控件和 ⋯；顶栏下不画线，内容滚到顶栏下面时才出现 0.5px 的细线，线画在内容之上，不占高度
- **侧栏**：顶部一行是范围胶囊和「新任务」（定时页是「新定时」）。「新任务」是级 3 加细边的次级按钮、墨色字和图标，不是实心墨色：它一直在，不需要用最重的颜色喊，实心的墨色留给眼下的主操作（允许、发送、开始）。往下依次是大标题（22 / 700）、副标题、筛选框、列表，底部是连接状态、会话 / 定时分段控件和齿轮。大标题、分组标题、筛选框和行首的状态图形的左边缘在同一条线上（距侧栏左边 20），行的文字在状态图形右边。大标题下面没有副标题时，大标题自己留出下边距，不贴着筛选框。行：标题 13 / 600，摘要 12，时间和第三行 11，上下内边距 8，行间不留空，圆角 10；选中行是级 3 的小卡，悬停是 5% 的薄层。列表里等你的事排最前，然后是进行中和已结束
- **会话**：对话列最宽 760，居中，输入框、停靠卡和提示与它同宽同对齐线（左右边缘对齐，卡的内边距 16 / 24）；停靠卡里的决定按钮靠右、各至少 120 宽，「允许，这类请求以后不再问」这样的次要链接在同一行的左侧；并排时两栏各自内边距 24。你的消息是级 2 的圆角 14 的气泡，正文 15 / 1.55。回复里的代码块是级 2 加 0.5px 细边、圆角 14，顶上一行左边写语言名（`data-lang`，没有写就空着）、右边是复制；工具行 12 号等宽、`ink2`；两轮之间的「本轮用时」分隔线用更淡的细线。输入框是圆角 14 的框，不是胶囊：文字占满整个宽度，「＋」和发送键在它下面单独一行（左边「＋」、右边发送），文字多了框往上长。能写字的框（会话和新任务的输入框、新定时的输入区）用比卡稍亮的底（暗 #26262b，亮同级 2）和一直在的 1px 细边（暗 rgba(255,255,255,.14)，亮 rgba(0,0,0,.10)），聚焦时细边变亮（.28 / .24），占位字用 `ink2`；「＋」和发送键都是 32 的圆钮。终端是嵌在主区域里的圆角 14 的深色面板（`term` 底），只看终端时占满主区域，四周留 24
- **新任务**是主区域本身：内容宽 640，居中，垂直位置在主区域上 38% 处，不在正中；一句话 17 号；输入框和会话的输入框是同一种画法，可写的区域最少三行；下面一排控件高 32。输入框比页面略微抬起：圆角 16，细边之外加一层很淡的投影，字 16 号；「＋」的左边缘和输入的文字对齐；「⌘↵ 开始」用 `ink3`。句子里的机器、项目、CLI 和输入框里的设置摘要点开的都是贴在那个控件下面的菜单（见「弹层」），画法相同，箭头都朝下
- **设置及子页**（设置、设备、电脑、客户端、额度、项目管理、新定时）：单列宽 640，居中；页面标题 28 / 700；分组标题和卡内文字对齐到同一条线（距列边 32）。电脑卡和分组列表是级 2、圆角 14，行高 44，行尾的值 `ink2`、箭头 `ink3`，开关用绿色；不在线的电脑也是同样的实心卡，只是名字用 `ink2`、点是浅灰
- **弹层**：菜单、对话框和选择都按第 2 节「宽屏表面」画浮层：级 3、0.5px 细边、统一投影。对话框圆角 18、居中、宽 460（确认框 360）；标题 15 / 600 靠左，右上角是「完成」，没有「完成」的放一个 ✕；确认框的按钮靠右，「取消」在左、确认在右。弹出菜单（⋯、范围、从控件上做的选择）圆角 14，菜单项高 32、圆角 8，组与组之间一条细线，不画成卡；弹层里的分组列表是级 2
- **空状态**：没选任务时，主区域居中一句 15 号 `ink2` 的话加一个次级按钮（定时页是「选一个任务查看结果」和「新定时」）；没选会话时主区域就是新任务
- **标题与路径**：标题过长用省略号截断；路径从中间截，开头和最后一段留着，完整路径是悬停提示
- **反馈**：每个能点的东西都有悬停和按下。行换底色（5%、8%）；墨色按钮悬停向反方向变 6%、按下缩到 0.98；文字按钮悬停有 5% 的圆角底；图标按钮悬停出现圆形底；过渡用快档。键盘焦点是 2px 蓝色的环，外扩 2px，圆角跟随，只在键盘操作时出现（`:focus-visible`）；输入区用细边变亮表示聚焦。弹层打开时焦点进入弹层，Tab 在其中循环，关闭后回到原来的地方。可点的是手形光标，可输入的是文本光标，禁用的是默认光标和 40% 不透明度。滚动条是细的，悬停时才显出；选中文字的底色是蓝色 28%
- 设置类页面和会话的宽度、间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48，字号只用第 3 节宽屏那一组

**长内容、大量内容与大字号**：界面稿里的文字都是短示例，实现要按下面处理，不靠示例长度撑住布局。

- 字多：标题、元信息、摘要一行放不下就省略，高风险词（如完全放行）放在前面，不会被省略掉；路径、命令、代码可以在任意位置换行，不撑出屏幕；消息正文完整显示，待发气泡最多 4 行、点开看全文
- 内容多：列表都有上限和「还有 N 个」入口。手机主页等你的事是一张终端卡加最多三行，再多写「还有 N 件」，进行中最多 5 个；宽屏侧栏（网页 ≥900 宽、平板）这两组不截断、不出「还有 N 个」，和已结束的一起整列滚动；已结束的先列 30 个、滚到底再加载，排队超过 3 条只显示前 2 条；项目超过 8 个时选项目弹层和范围菜单带搜索，范围内会话超过 8 个时主页带筛选框；聊天往上翻时分段读取更早的记录，读到开头时最上面是一行不带横线的「开始时间 · 目录」（不是当天的写出日期），带横线的分隔只用在两轮之间、分叉处和会话结束处；连续的工具调用、多张图都折叠
- 网页聊天回看：离开底部 60px 且不再跟随时，显示现有玻璃胶囊「回到最新消息」；有新消息时改写「N 条新消息」。点击回到末尾并继续跟随，回到底部附近后消失。Android / iOS 保留现有行为。
- 字号大：跟随系统字号，至少验证到 200%。行高随内容增长，不写死高度；左右两项放不下时右项换到下一行靠右，不压缩成一字一行；会话顶部的标题始终一行，放不下就省略；按钮文字可以换行，点击区不小于 44×44

## 7. 对话正文

agent 回复里的 Markdown。回复是手机上一列窄文字里的一句回答，不是一篇文档：结构靠留白分出来，不靠放大字号、描边和底色。

三端各有一个解析器，读法由共用的样例 `testdata/markdown/cases.json` 约束：网页的 `markdown.cases.test.ts`、Android 的 `MarkdownCasesTest.kt` 和 iOS 的 `RAMarkdownTests/CasesTests.swift` 都跑它，改读法先改样例。文字始终是文字，不当 HTML 插入。

**间距**：三档，相邻两块之间取下表里对得上的第一条。

| 位置 | 间距 |
|---|---|
| 回复的第一块之前 | 0 |
| 分隔线的位置 | 24 |
| 标题或加粗小标题紧跟在另一个标题后面 | 12 |
| 一二级标题之前 | 24 |
| 三级及以下标题、独占一行的加粗小标题之前 | 16 |
| 标题、加粗小标题之后 | 8 |
| 表格之后 | 16 |
| 段落后面紧跟列表 | 8 |
| 其余的块之间（段落、列表、代码块、表格、引用） | 12 |
| 列表项之间 | 4；列表里有一项会折行时，这个列表的各项之间 8 |
| 列表项和它的子列表之间 | 4 |
| 列表项里的段落、代码块、表格、引用之前 | 8 |

引用和列表项里面不分标题前后，块之间都是 12 和 8。

「会折行」按内容判断，不按当前屏幕实际折没折：一项里有换行，或显示出来的文字超过 40 个半角字符的宽度。宽度是估算：U+2E80 以后的字符（中文、日文、韩文、全角符号和大多数 emoji）算两个，其中半角片假名这类半角形式算一个，其余都算一个；差一两个字符只影响恰好卡在界线上的列表。项和行一样密时，几项折行的文字读起来像一整段；按内容判断，两端和不同宽度的窗口里同一个列表间距相同。

**各元素**

| 元素 | 画法 |
|---|---|
| 正文 | 17 号、行高 1.55、`ink`；过程中的说明（commentary）用 `ink2`。段内的单个换行保留 |
| 标题 | 一二级 20 / 600，三级 17 / 600，四级及以下 15 / 600 `ink2`；行高 1.35。不画下划线 |
| 加粗小标题 | 整段只有一行加粗（可以带一个冒号）时，字不变，只按三级标题留白：CLI 常这样写小标题 |
| 加粗、斜体、删除线 | 600；斜体；删除线加 `ink2` |
| 行内代码 | 等宽 15 号、`fill` 底、圆角 6、左右内边距 5；折行时每一段都有圆角。在一二级标题里用 17 号 |
| 链接 | 只有 http(s) 的目标能点，`blue`；裸写的网址也能点：到空白或句子自己的标点（全角标点、破折号、弯引号）为止，末尾的半角标点和没有配对的右括号不算进去。其他目标（多是本机路径）显示成等宽 15 号 `ink2`，不能点 |
| 列表 | 缩进 22，序号到两位数时这个列表缩进 32；圆点和序号用 `ink2`，序号用等宽数字；第二层起用空心圆 |
| 任务列表 | 行首是 1em 的 `square` / `square-check`，`ink2`；做完的整行 `ink2`，不加删除线 |
| 代码块 | `gbg` 底、不描边、圆角 14、内边距 10 × 14、等宽 13 号行高 1.5、`ink2`；不换行，放不下时块内横向滚动。手机不加顶栏，不写语言名，右上角是 16 的 `copy` 图标，`ink3`，可点区域 44，代码末尾留出图标的宽度，横向滚到头时没有字压在图标下面；宽屏的块是级 2 加 0.5px 细边，顶上一行（高 32）左边写语言名（12 号等宽 `ink2`）、右边是复制，下面一条细线，代码不再和图标抢位置 |
| 长代码块 | 超过 16 行时只显示前 12 行，底部一行「展开全文」（13 号 600 `blue`，向下的 `›`），行尾 13 号 `ink2` 写「共 N 行」；就地展开后是「收起」和向上的 `›`。按行数截，不按高度截 |
| diff | 写明 `diff` 或 `patch` 的代码块里，`+` 开头的行用 `green`，`-` 开头的行用 `red`，其余不变 |
| 表格 | 只画行间 `sep` 细线，最后一行下面不画；不画竖线、外框和表头底色。表头 13 号 `ink2` 不加粗、上方不留内边距，单元格 13 号行高 1.45、顶对齐；上下内边距 8，列间距 24，第一列从正文左边开始。宽度随内容，不拉满 |
| 表格的对齐 | 分隔行写了对齐就照它；没写时，一列里有内容的格子显示出来全是数量（数字带符号、货币或短单位，加粗和行内代码不影响）就右对齐并用等宽数字 |
| 宽表格 | 单元格最窄 34、最宽 240，超过就折行；整张放不下时横向滚动，手机上一直滚到屏幕边；右边还有内容时右缘 32 渐隐 |
| 引用 | 左边 2px `faint` 竖条、内边距 12、文字 `ink2`；里面可以有段落、列表和代码块 |
| 分隔线 | 不画线，只留 24 的空白，回复开头的不留：带横线的分隔只用在两轮之间、分叉处和会话结束处（第 6 节） |

- **不做语法高亮**：颜色只表达状态和可操作性（第 2 节）。diff 的增删是这条的唯一例外，因为它是内容的含义，不是装饰
- **手机的代码块不加「语言名 + 复制」顶栏**：那是聊天类产品的样式，语言名在手机上也没有用；宽屏有桌面的余地，加这一行，让块读起来是一个对象
- **回复里的长代码就地展开，不进整页**：对话本身就是一整页的滚动，展开后还能对着上下文读；停靠区里的命令也跟着内容区滚动，只有计划可以从「展开全文」进整页（整页里还有更多选项）
- 宽屏会话区的正文按第 3 节宽屏那一组（正文 15、行内代码和路径 13，一二级标题 17、三级 15、四级 13），其余同上表
- 图片、HTML 标签、脚注、公式不渲染，按文字显示

## 8. 文案

- 写结果和下一步，不写实现：「MacBook 不在线，连上后才能恢复」，不写「连接失败 (ECONNREFUSED)」；原始错误放进「详情」
- 会话结束时先说原因：手动结束写「会话是被手动结束的。」；定时任务关闭的写「定时任务运行已结束，会话自动关闭了。」；空闲太久被 daemon 关闭的（`idle_closed`）写「会话长时间没有活动，已自动结束。」；daemon 的详情以「the login shell」开头（客户端开的会话里登录 shell 没能启动 CLI，[architecture §6](architecture.md#6-接入-codex)）时写「电脑上的登录 shell 没能启动 CLI（原文）。请检查电脑上的 shell 配置，比如 ~/.zshrc。」，超时那条在括号后加「，可能卡在等待输入」；其余写「tmux 会话已经不在了。」这句三端逐字一致，改就一起改
- 说清是哪一段出了问题，并且只说知道的：本机没网时不写「电脑离线」，连不上服务器时不沿用断线前的「运行中」
- 按钮用动词，两到六个字；带省略号「…」表示还会再确认一次
- 时间窗口统一写「5 小时」「7 天」，不混用「本周」
- 同一个对象全局同名：电脑是会话执行的位置，在新建和会话设置里作为字段名时写「电脑」；客户端是操作会话的入口；设备是两者的合称
- **设备的名字**：用户起的名字优先；没起名的客户端叫「平台 · 型号或系统」，取自它在设备元数据里自报的 platform 和 description：网页「Chrome · macOS」（浏览器 · 系统，读不出系统时只写浏览器，什么都没有写「浏览器」），Android「Android · <机型>」，iOS 写「iPhone」「iPad」，都读不出写「客户端」。只有账户里另一个客户端的默认名和它相同时，才在后面加「 · 」和设备 ID 后 4 位区分。不在首次打开时弹窗要求起名，改名在「设置 › 客户端」里
- **来源**：消息、系统行（如「Safari · iOS 将模式切到 计划」，名字和后文之间空一格）和工具行右侧的「已允许 · Android · Pixel 9」按同一套写法：本客户端做的不写来源，账户里有别的客户端也一样；电脑终端里输入的（daemon 记成本地，或客户端自己判断是在终端里输入的）一律写「<机器名> 终端」，不写「本地终端」；其他客户端写它的名字；设备列表还没读到时写「另一客户端」，列表读到了且查不到时才写「已移除的设备」，不写设备 ID；daemon 没记录来源的消息不写，审批、提问在别处处理了写「另一端」
- 数值和单位之间空一格，如「24 / 256 MiB」「2 分 12 秒」
- **配对说明**按实际流程写：当前管理端（网页、Android 或 iOS Client，只有一个）打开「设置 › 添加设备」，显示二维码和 8 位配对码；新设备扫码（Android、iOS）或输入配对码（网页只能输入）。不写「用手机扫这台设备的二维码」这种反方向的说法。统一称「管理端」「当前管理端」「接任设备」，具体设备写名字（如「管理端（Pixel 9）」），不用限定管理端平台的称呼。下面几句三端逐字一致，改就一起改：
  - 加入页（Android、iOS）：「在管理端打开「设置 › 添加设备」，扫它显示的二维码，或把 8 位配对码填在这里。」
  - 加入页（网页，不提扫码）：「在管理端打开「设置 › 添加设备」，把它显示的 8 位配对码填在这里。」
  - 非管理端且没有电脑的空状态：「还没有电脑。在管理端（<名字>）上打开「设置 › 添加设备」，把电脑加进来。」管理端保留一句说明和「添加设备」按钮。
  - 非管理端的设置/设备页：「要添加电脑或客户端，在管理端（<名字>）上打开「设置 › 添加设备」。」

- 未登录页的三个入口同名同序：「创建账户」「加入已有账户」「用恢复码找回管理权」。管理能力取决于验签状态中的 Client / AuthorityID，不取决于平台；Machine 不显示接任入口。
- 设置分组顺序：电脑、客户端、账户安全。「添加设备」在电脑分组的最后一行，使用 `plus` 图标和蓝字；非管理端在同一位置显示指向管理端名字的固定句。「账户安全」分组进入同名页面。
- **账户安全页**三端同序：顶部有恢复申请时显示橙字提示条「有人正在用恢复码申请接管管理权，<时刻> 后生效。不是你本人就现在否决。」，仅管理端右侧有「否决」；其后仅在存在 pending 时显示「未完成的安全操作 ›」。第一组无分组标题，依次「当前管理端」（本机或设备名）、「远程控制有效期」（实际到期时刻），管理端再加蓝字「现在续期」。组下说明「回到管理端时自动续期；过期后远程控制暂停，聊天和历史仍可查看。」网页追加「网页关闭或冻结时无法续期。」；iOS 追加无后台提醒的固定句。非管理端另写「请打开<管理端名称>续期」，名字两边不加空格。第二组管理端有「恢复码 ›」「交接管理权 ›」，非管理 Client 只有「接管管理权 ›」；Machine 没有接任入口。恢复码和交接分别进二级页，不把操作铺在总览。
- 界面不使用协议里的证书术语，统一写「远程控制有效期」。显示当前 head 已装证书的实际到期时间，不用当前时间加 72 小时替代。时刻一律中文 24 小时制、不带秒：今天/明天 HH:mm，其他日期 M月D日 HH:mm；按本地日历比较日期，跨午夜、年和夏令时同规则。
- 配对码以「1234 5678」两段显示；截止只写「有效期至 05:02」。添加设备页顶部不重复页面标题，说明固定为「电脑：运行 remote-agent account join，输入下面的配对码。客户端：扫二维码或输入配对码。」这句是给新设备看的，网页同样显示扫码说明。
- 恢复申请待处理时，首页和设置都保留醒目的处理入口和可生效时间；读取失败不能当作没有申请。网页安全通知独立于会话提醒，不承诺推送必达。
- 网页建账户/接任前固定提示：「此浏览器将是唯一管理端。清理网站数据或换浏览器会丢失管理密钥；恢复码必须离线保存。日常建议用 App 管理。」显式请求 `navigator.storage.persist()` 并显示真实结果，成功：「已请求浏览器保留数据」；失败：「浏览器没有承诺保留数据」。持久存储不保证用户清理数据后仍能恢复。
- iOS 建账户/接任前固定提示：「iOS 版没有后台安全提醒，建议每天打开一次，以免错过恢复申请。」
- 退出确认沿用 `authorityExitAdvice` 三句：有未核实操作：「安全操作结果尚未核实，请先继续原操作；退出会删除唯一完成材料。」唯一管理端：「此浏览器是唯一管理端，建议先交接；退出会删除管理密钥，没有恢复码备份将丢失管理权。」其他成员：「退出会删除本机密钥，需要重新配对。」原生端按平台改指代本机的词，不更改后果和顺序。
- CLI 核对图案提示：「先在这里确认，再在管理端上允许」。普通换码和交接 offer 必须先显示新恢复码并确认离线保存，再发布；存储失败时保留材料和错误，不显示成功。重启后继续原创建/紧急恢复草稿，不另建竞争状态；没有确认备份就完成原恢复时，进入账户立即引导换码。

### 文案源与翻译

产品文案按功能语义命名 key，不按组件层级或原句生成 key。统一写入 `i18n/messages/<domain>.json`；先原样抽取中文，再给英文初稿，抽词提交不同时润色中文。相同含义共用 key；「关闭界面」Close 与「关闭设置」Off 必须分开，不因中文相同就复用。完整句子带命名参数，禁止拼接可翻译的句子碎片。数量句用 plural；明确有限选项用 select，复杂嵌套先拆成可审查的语义消息。语言资源的契约和阶段边界见 [architecture.md §20](architecture.md#20-界面语言与文案资源)。

每条译者说明包含页面/动作、按钮或读屏等用途、变量来源、空间约束与操作后果；变量必须有类型和例值，例值不得含真实机器、账户或路径。术语以 `i18n/glossary.json` 为准，用户/CLI 内容和原生 CLI 选项保留原文。英文由开发者起草，双语文案负责人校对，涉及权限、恢复、重发的文案还需功能负责人复核后才标 reviewed；draft 可入库用于测试，不能作为已审语言开放。

英文变长时允许操作和说明换行或调整纵向布局，不缩字、不省略安全含义。用最小屏、200% 字号及长名字检查触摸区与读屏标签。品牌、协议常量、代码和用户样例不能机械翻译。旧写死文案由 lint 基线暂存，新命中必须抽取或在精确 allowlist 说明它为何不是产品文案，不通过刷新整个基线掩盖新增债务。

## 9. 审查清单

新增或修改界面稿时逐条看：

- [ ] 管理端、非管理 Client 和 Machine 的入口与提示分别核对；恢复码未确认不能发布换码或交接 offer
- [ ] 每屏最多一个墨色实心按钮（深色卡里的白色按钮另算），且它确实是这屏最该做的事；空状态没有在页面中间再放墨色按钮（还没有电脑时的「添加设备」除外）
- [ ] 颜色只表达第 2 节里的含义，同一含义在各画面同色；橙色只用在等你处理的事上
- [ ] 要读的文字只用 `ink` 和 `ink2`；状态词、元信息都是 `ink2`，没有加粗或上色，状态由行首图形表达
- [ ] 大标题那句话和列表里的数一致，断线时说的是连接状态；断线时等你的事和标签上的数字没有消失，按钮置灰
- [ ] 分组标题说过的属性没有在行内重复
- [ ] 字号、圆角都在第 3、4 节的取值里
- [ ] 没有导航栏和标签栏；模糊只用在小块玻璃上，降低透明度时有不透明的样子；阴影只给浮起的东西
- [ ] 图标网页和 Android 来自 Lucide、iOS 对应第 5 节的 SF Symbols，含义符合第 5 节，进入新页面和就地展开的箭头方向没有混用
