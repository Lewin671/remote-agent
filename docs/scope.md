# 项目边界

本文档定义 remote-agent 做什么、不做什么，以及各组件、各信任域之间的边界。
新需求先对照本文档：落在「不做」里的，需要先改这份文档再动代码。
技术决策见 [architecture.md](architecture.md)，还没定的问题见 [plan.md](plan.md) 的「待确认」。

## 1. 要解决的问题

- 在多台电脑上跑 AI 编程 CLI，人不在电脑前时，也能在手机或其他设备上查看、追问、审批、打断
- 不经过飞书等第三方平台，消息内容只有自己的设备能解密
- CLI 以**原生交互形态**运行，不走 SDK / app-server 这类程序化接口；在电脑上直接用终端，和在手机上操作的是**同一个会话**

## 2. 目标用户

**一个账户就是一个人。** 账户内没有团队、共享和权限分级：成员设备有各自的身份和交换密钥；账户只有一个管理端，由 Android、iOS 或网页中的一个 Client 成员担任，用其设备密钥签成员状态和租约，不接管原生 CLI。电脑 daemon 是 Machine，不能成为管理端；平台名称不参与管理资格判断。

**一台中继可以承载多个互不相干的账户**（2026-10-17 起）。我们运营一台公共中继 `ra.remote-agent.top`，让别人不用先买服务器就能试用；别人也可以照公开文档自己部署，自部署默认仍只建一个账户。账户之间互相看不见、改不动对方的任何东西：不只是内容（本来就是密文），也包括元数据、设备、推送和资源配额。中继仍然读不到任何账户的内容，信任边界见第 4 节。

公共中继是试用性质：有配额和滥用限制，不承诺数据长期保存，也不提供客服。要长期、不受配额限制地用，就自己部署一台。

## 3. 组件与职责

```
┌──────────── 每台电脑 ────────────┐        ┌──── VPS ────┐        ┌── 各端客户端 ──┐
│ remote-agent（Go 单二进制）      │ HTTPS  │ remote-agent│ HTTPS  │ Web / PWA      │
│  daemon + 本地 CLI 命令          │◄──────►│ -server（Go）│◄──────►│ Android App    │
└──────────────────────────────────┘ + WSS  └─────────────┘ + WSS  │ iOS App        │
                                                                   └────────────────┘
```

通信方式、部署和技术决策见 [architecture.md](architecture.md)。

| 组件 | 负责 | 不负责 |
|---|---|---|
| `remote-agent`（每台电脑一个） | 在 tmux 里启动和托管 CLI；读取 transcript 并转成统一事件；接收 hook（审批、轮次边界）；排队并注入输入；转发终端字节流；加密、解密和签名；上报本机的项目 | 另存一份对话原文（transcript 本身就是本地的数据源，daemon 只保存由它派生的事件、待发消息和读取进度）；替 CLI 做决策 |
| `remote-agent-server`（VPS） | 设备鉴权；按路由转发密文；存储会话事件的密文；存储公开签名的成员状态链并按修订号 CAS 可变对象；收到删除状态时吊销设备；发送推送 | 解密任何内容；理解消息语义；分组和搜索；替离线的 daemon 排队指令；提供网页代码（网页放在 Cloudflare Pages）或 App 安装包；签成员状态 |
| `web`（PWA） | 配对设备；解密和渲染；按项目分组；聊天视图和终端视图；权限审批；作为当前管理 Client 时管理账户 | 直接连接 daemon（一律经 server 转发） |
| `android`（原生 App） | 和 PWA 相同，另外在系统通知里显示审批并直接允许或拒绝；作为当前管理 Client 时管理账户 | 直接连接 daemon（一律经 server 转发） |
| `ios`（原生 App） | 和 PWA 相同，终端用原生视图；可作为当前管理 Client | 直接连接 daemon（一律经 server 转发）；首版无后台安全提醒和通知审批，不以 APNs 为管理能力的前置条件 |

管理能力按 Client 角色定义，包含建账户、批准加入、移除、续租、交接和恢复；网页与 iOS 的管理流程仍在实现，当前进度见 [plan.md](plan.md)。

## 4. 信任边界

**server 被视为不可信**：VPS 被攻破时，泄露的只能是元数据，不能是内容。

| 数据 | server 能看到明文吗 |
|---|---|
| 消息、工具调用、终端输出、审批内容、会话里的图片 | 否（图片的数量、大小和时间能看到） |
| 项目名、路径、git 远程地址、会话标题、机器名 | 否（放在加密的元数据里） |
| 设备 ID、机器 ID、会话 ID、事件序号、时间戳、密文长度 | 是（路由必需） |
| 设备成员关系、签名状态链、租约起止时间 | 是（公开签名状态，不含内容） |
| 定时推送元数据（`NOTIFY_KIND_SCHEDULED`、`TURN_ENDED` 的出现模式） | 是；server 可以据此推断会话在跑定时任务、发生过定时结果通知（无法据此区分 Agent 与 daemon），包括用户自己的对话；任务 ID、标题和正文仍加密 |
| 会话是否归在定时任务下 | 是（已结束分页排除这些会话必需；未结束会话照常返回；任务 ID、标题和内容仍加密） |
| 会话有没有结束、什么时候结束 | 是（分页列出已结束的会话必需；其余状态，如运行、等待审批，仍在加密的元数据里） |
| 设备公钥 | 是 |
| 根密钥、设备私钥、恢复码、内容密钥、会话密钥 | 否 |
| 推送内容 | Web Push 只包含通用文案（如「有新的审批请求」）；Android 的推送可以带内容，但必须是 daemon 端到端加密的密文，server 和推送服务（FCM）只能看到密文、推送 token、时间和长度 |
| 网页代码 | 不由 server 提供，否则被攻破后可以替换 JS、绕过加密 |
| App 安装包 | 不由 server 提供，自己签名、自己安装；APK 签名密钥和 Cloudflare 账号一样是关键资产 |

硬性规则：
- 任何明文内容不得出现在 server 的日志、数据库或推送 payload 中
- daemon 和客户端的日志里也不得打印消息正文或密钥；调试时只打印 ID 和长度
- App 在本机解密后显示的通知，锁屏上只显示通用文案。默认连解锁后也只显示通用文案，点开再审批；在 App 设置里打开「在通知里显示内容并直接审批」后，审批内容才交给系统通知，代价是它可能留在通知历史里、被有通知读取权限的 App 读到
- 加密只用标准原语：AES-256-GCM、X25519、Ed25519、HKDF，不自己发明密码算法或密码学构造（应用层的报文格式照常自己设计，见 [architecture.md](architecture.md)）
- 管理端私钥就是当前管理 Client 的设备私钥，只留在该设备的本地存储；原生端不进云备份和设备迁移。恢复码只显示一次，由用户离线保存，客户端不持久保存恢复 seed；它是紧急管理权凭证，不直接解开旧密文，但恢复成功会控制保留电脑。管理签名只在活跃前台进行，原生端还要求设备解锁；推送回调和网页 Service Worker 不能签管理操作。浏览器不提供与原生端相同的解锁保证，同源脚本能使用不可导出的密钥；网页托管与发布渠道属于信任边界，清理网站数据可能丢失唯一管理身份，见 [architecture.md 第 9 节](architecture.md#9-账户设备和密钥)

### 设备加入与移除

账户的唯一管理端是验签成员 head 指定的 Client。它用设备 Ed25519 密钥、按状态签名标签签成员状态和租约，恢复声明由恢复码签；新设备必须由当前管理端发起配对，双方核对四个图案、候选设备先确认、管理端再允许。根密钥、旧会话密钥、已移除设备的私钥或中继管理员权限都不足以产生新的有效授权。所有保留设备的程序、操作系统、私钥和本地安全状态不能被攻击者回滚；网页代码与发布渠道也必须可信。

删除设备只需在当前管理端操作一次。管理端签出新的成员状态和内容密钥并上传，server 一收到就清除被删设备的登记、登录 token 和推送；保留其在中继上的机器、会话、事件和图片，删除记录是另一个需要确认的操作。保留设备在 60 秒内后台拉取新状态；不需要逐台确认，也没有完成证明。新内容和控制使用新的内容密钥，即使中继把后续密文交给旧设备，旧设备也不能解开或授权。最坏情况下，中继把删除状态扣住不给某台执行电脑，那台电脑会继续接受被删设备的控制，直到它本地状态的租约过期，最多 72 小时。已下载内容、历史密钥和已进入原生 CLI 的操作不能收回；更改成员前已经产生的密文仍属于旧历史。

成员状态的租约是 72 小时。管理端在前台时按续期条件签发新证书；租约过期后远程控制和新内容上传暂停，内容在本机缓冲，已存历史和本地原生 CLI 继续可用。管理端不能普通删除，也没有第二管理端；正常交接由旧管理端签署、轮换内容密钥并移除自己，保留可达历史；管理身份丢失时用恢复码，诚实中继等待 48 小时，期间原管理端可否决；恢复状态把原管理端移出成员表。恢复后的客户端不能直接解开恢复前的密文；被攻破的成员电脑能读账户范围内容，但不能向其他机器发送控制。保留电脑仍在运行，会持久保存并重试发布当前时期的独立 checkpoint，所以新管理端能看到还在进行的会话，更早的历史只有保留设备能读。中继仍可以拒绝转发、扣留或删除密文，并看见路由和成员元数据；端到端安全不保证可用性。旧格式历史的内容和来源未验证，只供阅读，不能建立当前待审批、输入投递或运行状态。协议及升级步骤见 [architecture.md](architecture.md#9-账户设备和密钥) 和[升级指南](self-hosting.zh-CN.md#升级到手机管理端协议-10)。

## 5. MVP 范围

### 做

- **支持的 CLI**：只有 Codex
- **设备配对**：只有当前管理 Client 能发起和批准；双方核对图案后固定安全域，独立交换密钥用于分发内容密钥；各设备用 Ed25519 签名 challenge 登录，不设密码
- **账户管理**：一个管理端，Android、iOS、网页均可作为管理 Client；当前管理端批准新设备、删除设备、续租约和交接，用恢复码紧急恢复管理权；Machine 只能作为普通成员加入
- **多机器**：每台电脑跑一个 daemon，客户端能看到所有机器
- **会话**：新建、列表、查看历史、发消息、中断、结束；客户端新建以第一条文字、图片或文件消息开始，不提供只启动终端的空会话入口
- **本地入口**：`remote-agent codex` 在 tmux 里启动 Codex 并在当前终端 attach；断开后会话继续在后台运行
- **定时任务**：由 daemon 持久化和调度，支持指定时间、固定间隔、当地日历时间和本轮结束后延时；可恢复原会话或新开原生 CLI 对话。新开对话归在任务下，用户明确恢复或回复后进入自己的会话列表；定时轮次默认在完成后请求通知，Agent 已主动通知则不补发；可关闭任务级完成通知，仅由 Agent 按需通知。审批和提问照常提醒。网页、Android、iOS 提供独立定时入口、任务管理、运行历史、对话定时条与静默轮折叠；离线可读上次任务状态，不能修改。本地 CLI、托管会话专用 MCP 与加密机器指令共用任务模型；设计与通知边界见 [architecture §18](architecture.md#18-定时任务)，实现和验收状态见 [plan.md](plan.md)
- **daemon 更新**：本机 CLI 手动更新及显式开启的系统定时更新；限正式产物、相同协议和存储代数，失败恢复旧二进制；不自动迁移数据或升级中继
- **daemon 重启后重新接上**仍在运行的 tmux 会话
- **聊天视图**：文本、推理摘要、工具调用和结果、轮次开始和结束、token 用量
- **会话设置**：切换模型和 reasoning effort；上下文占用提示和压缩
- **终端视图**：通过 tmux control mode 获取实时字节流，加密后经 server 转发，**不落库**；进入终端时自动把 tmux 窗口适配到这块屏幕，可「还原」；手机上提供特殊按键栏
- **权限审批**：需要用户审批的请求经 Codex 的 `PermissionRequest` hook 转到客户端，**超时默认拒绝**；会话开着 `auto_review` 时由 Codex 自己判断（见 [architecture.md](architecture.md)）
- **回答模型提问**：Codex 的 `request_user_input` 在客户端显示成选项卡片，点选即回答
- **多端输入**：按到达顺序注入，不加锁
- **按项目分组**：分组在客户端完成，项目怎么判定见 [architecture.md](architecture.md)；主页按范围（全部项目或某个项目）列出会话，可以按标题筛选
- **推送**：Web Push，在一轮结束和有审批请求时提醒
- **部署**：server 部署在 VPS，TLS 必须开启

### MVP 之后要做

- **Claude Code**：和 Codex 同等对待，同样以原生 TUI 跑在 tmux 里，客户端能做的操作两者一致；`remote-agent claude` 是本地入口，新建会话时选 CLI。设计见 [architecture.md](architecture.md) 第 16 节，实测见 [claude-code-notes.md](claude-code-notes.md)
- **客户端界面**：支持 Codex / Claude Code 的统一输入区和能力差异；设备页按 CLI 展示可获取的账户额度及缺失、过期状态；项目管理支持添加项目、常用置顶和从列表移除（移除保留会话和历史，不移动或删除本地目录；要再用就重新添加这个目录）；连接检测按段显示到服务器和到每台电脑的往返延时；会话可以重命名，也可以分叉（用 CLI 自己的分叉从当前对话另开一个会话，原会话不动）；区分电脑与客户端，展示多端消息来源和共享状态，设备名称保持端到端加密；显示会话里出现的图片（在电脑上粘贴的、Agent 查看或生成的），也能从客户端发图片和任意文件给 Agent；文件原样发送，包含元数据，Agent 按本机路径读取（[session-files.md](session-files.md)）。界面见 [design/client-v53.html](design/client-v53.html)
- **iOS 原生 App**：覆盖 PWA 的全部功能，终端用原生视图；只给自己用，不上架应用商店。首版无推送和通知审批，管理端没有后台安全提醒，建议每天打开一次；不保证在 48 小时内看到恢复申请。真机分发渠道仍未定（[plan.md](plan.md) 的「待确认」）。选型见 [ios-client.md](ios-client.md)，进度见 [plan.md](plan.md)
- **Android 原生 App**：覆盖 PWA 的全部功能，终端用原生视图；审批请求以富通知显示，解锁后可以在通知里直接允许或拒绝。只给自己用，侧载安装，不上架应用商店；App 自己检查新版本、下载并交给系统安装，安装包来自本仓库的 Release。选型见 [android-client.md](android-client.md)，进度见 [plan.md](plan.md)

### 不做（MVP 之后再评估）

- Codex 和 Claude Code 以外的 CLI
- 显示 CLI 记录以外的文件：Agent 在回复里提到的本机文件，daemon 不去读
- 接管不是由 `remote-agent` 启动的 CLI 进程
- 桌面端原生 App
- 语音、feed、artifacts、数据统计
- 在客户端里浏览或编辑文件、查看 diff 面板
- 全文搜索（server 无法搜密文，客户端本地搜索对话内容留到以后；按会话标题筛选不在此列，已经做）

### 永远不做

- 通过 SDK、app-server 或 `--remote` 协议驱动 CLI
- 一个账户内的多用户、团队、共享会话（多个互不相干的账户共用一台中继不在此列，见第 2 节）
- 以任何形式把消息明文交给 server 或第三方
- 靠识别屏幕内容来获取结构化消息（屏幕只用于判断状态和终端视图）
